# 워크플로우 — 주제 한 줄에서 스토어까지

[README](README.md) 의 흐름을 단계 · 워크플로 · 승인 · 보고로 풀어 쓴 것입니다.
Claude 가 지킬 규칙 원문은 [seed/CLAUDE.md](seed/CLAUDE.md), 기기 세팅은 [SETUP.md](SETUP.md).

## 1. 단계별 — 누가 · 얼마나 · 주인이 하는 일

기간은 **서버 없는 단순한 앱**(화면 5~8개) 기준 어림입니다. 첫 앱은 파이프라인을 세우느라 두세 배 걸립니다.

| 단계 | 누가 | 기간(어림) | 주인이 하는 일 |
|---|---|---|---|
| S0 접수 | 주인 → 클라우드 세션 | 1분 | Claude 앱에서 `/new-app <주제>` |
| S1 조사 | 담당 세션 + `market-researcher` | 1~2시간 | 없음 (60점 미만이면 "안 만듦" 보고를 받음) |
| S2 기획 | 담당 세션 + `product-critic` | 1시간 | 없음. 기획서 요약이 오고, 멈추고 싶으면 "멈춰" |
| S3 설계 | 담당 세션 | 반나절 | 없음 |
| S4 구현 | 담당 세션 · CI | 3~7일 | 없음 |
| S5 검증 | 맥 미니 러너 · `qa-explorer` | 1~2일 | 없음 |
| S6 출시 준비 | 담당 세션 · `store-reviewer` | 1일 | **앱마다 처음 한 번** 콘솔 입력(5절) 15~30분 |
| (구글) 비공개 테스트 | 테스터 12명 | **14일** | 개인 계정이면 앱마다. 조직 계정이면 없음 |
| S7 출시 | 출시 창구 워크플로 | 애플 심사 1~3일 | **승인 버튼 한 번** |
| S8 운영 | 루틴 · 담당 세션 | 계속 | 하루 요약 읽기. 30/60/90일 판정 확인 |

주인의 총 개입: 주제 한 줄 + (처음만) 콘솔 30분 + 출시마다 버튼 한 번.

## 2. 누가 어디서 도는가

```
주인 (폰: Claude 앱 · GitHub 앱)
 │  주제 한 줄              ▲ 하루 요약 1번 · 승인 요청 · 막힘
 ▼                          │
클라우드: Projects 「앱 공장」 — 공장장(프로젝트 대화) + 앱마다 담당 스레드
 │  코드 · PR · 보고. CI 결과에 깨어나 고침. 결정은 프로젝트 기억에
 ▼
app-factory (비공개 · GitHub)
 ├ ci ............... GitHub 리눅스 러너
 ├ device-lab ....... 맥 미니 러너 (시뮬 · 아이폰12 · 안드로이드 폰)
 └ release-candidate  맥 미니(iOS) · 리눅스(안드로이드)
                      → TestFlight · 플레이 내부 테스트
 │
 ▼ 담당 세션이 실행 (승인 요청)
app-factory-ship (공개 · 코드 없음)
 └ ship ── [store-production: 주인 승인] ──▶ 애플 심사 제출 · 플레이 프로덕션
```

**세션과 기기를 잇는 버스는 GitHub 입니다.** 담당 스레드가 워크플로를 실행하고, 맥 미니 러너가
받아서 돌리고, 결과를 `lab-results` 브랜치와 PR 커밋 상태로 올리면 그 상태 이벤트가 스레드를 깨웁니다.
MyBody 때 주인이 전달하던 우편함(LOCAL-TASKS.md)이 이것으로 바뀝니다. 통로별 규칙과 메시지 형식은
[SESSIONS.md](SESSIONS.md).

세션끼리 직접 메시지(SendMessage)도 됩니다 — 맥 미니 세션이 Remote Control 로 연결돼 있으면
클라우드 세션에서 보입니다([문서](https://code.claude.com/docs/en/cross-session-messaging)). 다만 받는 쪽
권한 모드에 따라 승인 대기에 걸리고(5분 지나면 버려짐), 맥 미니가 꺼져 있으면 늦게 닿습니다. 그래서
**정해진 일은 워크플로, 급한 즉석 일만 메시지**로 씁니다.

### 담당 스레드가 계속 깨어 있는 법
- PR 을 열면 그 PR 의 CI · 리뷰 이벤트를 구독합니다(프로젝트 스레드는 자동) → 빨간색이면 그 이벤트로 깨어나 고칩니다.
  device-lab 결과도 PR 커밋 상태로 붙으므로 같은 통로로 깨어납니다.
- 긴 대기(맥 미니 시험, 애플 심사)는 스스로 점검 시각을 예약(send_later)해 두고 끝냅니다.
- 루틴은 **PR 과 릴리스 이벤트만** 받습니다(이슈 · 댓글은 안 받음). 그래서 주인의 지시는 세션에
  직접 쓰거나, 상황판 이슈에 쓰면 다음 하루 요약 루틴이 읽어서 해당 세션에 전달합니다.

## 3. 워크플로 다섯 개

MyBody 의 `apk.yml` · `ios-release.yml` 에서 검증된 부분(판 번호 = 커밋 수, 서명 결과물 확인,
맥 없이 iOS 서명)을 가져와 앱 이름을 입력으로 받게 일반화합니다. 아래는 설계입니다 — **첫 앱을
만들면서 실제로 돌려 확정**합니다.

### ci.yml — 모든 PR · main 푸시 (리눅스)
- 바뀐 경로로 대상 앱을 고름(`apps/<앱>/**`, `packages/**` 면 전부)
- `flutter analyze` · `flutter test`(위젯 · 골든) · `packages/` 시험 · `.claude/hooks/guard.test.js`
- 문구 검사(글자 수 · 금지어) · 글꼴 커버리지 · 스토어 규정 정적 검사([QUALITY.md](QUALITY.md) L5)
- 결과 요약을 워크플로 요약(Step summary)에

### device-lab.yml — 담당 세션이 실행 + 매일 밤 활성 앱 (맥 미니)
- 입력: 앱 · 커밋 · 묶음(`smoke` / `full` / `explore`)
- iOS 시뮬레이터(가장 작은 · 가장 큰 화면)와 안드로이드 폰들에서 Maestro 흐름
- 아이폰 12 실기기: Patrol(또는 integration_test) — Maestro 는 실제 아이폰을 공식 지원하지 않음
- 스크린샷: 라이트 · 다크 · 글자 크기 최대
- 시작 시간 · 앱 크기 측정
- `explore` 이면 `claude -p` 로 `qa-explorer` 헌장을 mobile-mcp 와 함께 돌림
  (`CLAUDE_CODE_OAUTH_TOKEN`, 구독 한도에서 차감)
- 결과: 요약 + 스크린샷 · 로그를 `lab-results` 브랜치의 `<앱>/<실행번호>/` 에 푸시 → 세션이 `git fetch` 로 읽음

### release-candidate.yml — S6 에 담당 세션이 실행
- iOS(맥 미니): IPA 빌드 · 서명 → TestFlight 업로드 · 내부 테스트 그룹에 붙임
- 안드로이드(리눅스): 앱별 업로드 열쇠로 AAB 서명 → **서명 지문 확인** → 플레이 내부 테스트 트랙
  (새 앱의 첫 AAB 는 콘솔에서 손으로 올려야 해서, 첫 판은 AAB 를 산출물로만 남김 — 5절)
- 결과물 검사: 번들 ID · 판 · 빌드 번호 · 권한 · `PrivacyInfo.xcprivacy` · targetSdk · 16KB 정렬
- 열쇠: `*_BETA_*` (테스트 트랙까지)
- iOS 서명: 러너가 지워지지 않는 맥 미니라 MyBody 의 "실행마다 인증서 발급" 이 필요 없습니다. Xcode 에 Apple ID 를
  한 번 로그인해 두고 **자동 서명**으로 빌드하고, 업로드만 `ASC_BETA_*` API 키로.
- 끝나면 문안 · 스크린샷 · `build.json`(판 · 빌드 번호 · 번들 ID)을 배포 열쇠로 출시 창구의 `queue/<앱>/<판>/` 에 넣음

### ship.yml — 출시 창구 `app-factory-ship` (공개 · 리눅스)
- 입력: 앱 · 판 · iOS 빌드 번호 · 안드로이드 versionCode · 배포 비율(기본: 새 앱 100%, 업데이트 20%)
- `environment: store-production` → **여기서 멈추고 주인 승인을 기다림**
- 승인 뒤: 자기 저장소의 `queue/<앱>/<판>/` 을 읽음 (개인 토큰 없음)
- iOS: fastlane `deliver` — 문안 · 스크린샷 · 빌드 지정 · 연령 등급 · 심사 제출(API 의 reviewSubmissions).
  통과하면 자동 출시, 사용자가 있는 앱은 단계적 출시(7일)
- 안드로이드: fastlane `supply` — 내부 테스트의 같은 versionCode 를 프로덕션으로, 배포 비율 · 등록정보
- 요약: 앱 · 판 · 제출 결과만 (공개 저장소라 기록이 보임)

### ship-control.yml — 출시 창구 (공개)
- 배포 비율 올리기(20% → 100%) · 배포 멈추기 · Shorebird 핫픽스 패치
- **모두 같은 승인 환경 뒤.** 프로덕션을 바꾸는 열쇠는 승인 없이는 어떤 잡에도 풀리지 않게 둡니다.
  (크래시가 치솟으면 Claude 가 "멈추기" 승인을 요청하고 알림을 보냅니다. 급하면 주인이 Play Console
  앱에서 직접 멈출 수도 있습니다.)

## 4. 승인 게이트 — 주인이 실제로 누르는 것

1. 폰에 알림 두 개가 거의 같이 옵니다:
   - Claude(담당 세션 또는 루틴): "습관 v1.0.0 출시 승인 요청 — 첫 판 · 실기기 4대 초록 · 링크"
   - GitHub 앱: "app-factory-ship: Review pending deployment"
2. GitHub 앱에서 실행을 열면 요약에 **상황판 링크**가 있습니다. 상황판 맨 위에 무엇이 바뀌었는지 ·
   시험 결과 · 스크린샷 · 알고 내는 문제 · 되돌리는 법이 있습니다.
3. **Approve and deploy.** 끝. (고칠 게 있으면 Reject 하고 세션이나 상황판에 한 줄)

잠금이 어떻게 겹쳐 있는지는 [SETUP.md](SETUP.md) 3절 「열쇠를 둘로 나누는 이유」.

## 5. 사람만 되는 칸 — 앱마다 처음 한 번

API 로 안 되는 것들입니다(2026-09 확인). Claude 는 S6 에서 **답을 전부 채운 `console-answers.md`** 를
만들어 두고, 주인은 콘솔을 열어 붙여 넣기만 합니다.

| 어디 | 무엇 | 걸리는 시간 | 왜 사람이 |
|---|---|---|---|
| App Store Connect | 새 앱 만들기(이름 · 번들 ID · SKU · 기본 언어) | 3분 | API 가 앱 생성을 안 받음(`POST /v1/apps` 불가). fastlane `produce` 는 Apple ID 로그인 + 2단계 인증이 필요 |
| App Store Connect | 앱 개인정보 보호(「영양 성분표」) 답안 | 10분 | 공개 API 없음 |
| Play Console | 앱 만들기 · 선언 체크 | 3분 | API 에 앱 생성 없음 |
| Play Console | **첫 AAB 올리기**(내부 테스트) | 3분 | 새 앱(초안) 상태에서는 API 가 초안 출시만 받음 |
| Play Console | 앱 콘텐츠: 콘텐츠 등급 설문 · 타깃 연령 · 광고 포함 · 앱 액세스(심사 계정) · 건강 앱 등 선언 | 15분 | 해당 API 없음. (데이터 보안 양식은 API 로 CSV 를 올릴 수 있어 Claude 가 함) |
| Play Console | (개인 계정) 비공개 테스트 12명 · 14일 → 프로덕션 액세스 신청 설문 | 테스터 모집 + 5분 | 구글 정책. 조직 계정은 면제 |

API 로 **되는** 것(ship 이 함): 문안 · 스크린샷 · 가격 · 출시 국가 · 연령 등급(한국 연령 등급 덮어쓰기 포함) ·
TestFlight 그룹 · 베타 심사 제출 · 심사 제출 · 플레이 트랙 업로드 · 단계적 배포 · 등록정보 · 데이터 보안.

계정 단위로 한 번(앱마다 아님): 계약 · 세금 · 은행 · 소규모 사업자 프로그램 · 결제 프로필 · 본인 확인.

### console-bot — 콘솔 칸까지 없애기 (첫 앱을 손으로 낸 뒤)
위 표의 칸은 전부 **웹 양식**입니다. 맥 미니에 Playwright 용 브라우저 프로파일(`~/lab/console-profile`)을 하나 두고 주인이 두
콘솔에 로그인해 두면, Claude 가 `console-answers.md` 의 값을 그 브라우저로 대신 채웁니다(스크린샷을 남기고, 제출 직전에 멈춰
상황판에 확인용 스크린샷을 붙임). 애플 · 구글 세션이 만료되면 「콘솔 로그인 필요」로 주인 할 일에 뜨고, Tailscale 화면 공유로
2단계 인증만 한 번. 정책상 금지된 자동화가 아니라 주인 계정으로 주인이 시키는 입력이지만, **2단계 인증 코드를 Claude 가
읽게 하지는 않습니다** — 그 한 번은 주인 몫으로 남깁니다. 스크립트는 첫 앱의 콘솔 화면을 보며 맥 미니 세션이 만듭니다.

## 6. 보고 체계

| 통로 | 언제 | 무엇 |
|---|---|---|
| **상황판 이슈** (앱마다) | 단계가 바뀔 때마다 본문을 고쳐 씀 | 단계 · 한 일 · 다음 · 막힘 · 주인 할 일 |
| **공장 이슈** `[공장] 오늘` | 매일 21:00 루틴 | 모든 앱 한 장 요약. 첫 줄이 「주인 할 일」 |
| **푸시** (Claude 앱) | 하루 요약 1번 + 주인이 해야 할 일이 생긴 순간 | 한 줄. "무엇을 해야 하나" 가 먼저 |
| **GitHub 알림** | 출시 승인 요청 | 승인 버튼 |
| **메일**(선택) | 애플 · 구글이 보낸 심사 결과 · 정책 경고 | Gmail 커넥터를 루틴에 붙이면 루틴이 읽고 요약 · 대응 |

**알리지 않는 것:** 기능 하나 머지됨, CI 한 번 빨갛다가 고쳐짐, 시험 통과. 이런 건 상황판과 하루
요약에만. 주인이 폰을 볼 때마다 할 일이 있어야 알림이 무시되지 않습니다.

알림 예:
- `습관 v1.0.0 출시 승인 요청 — 첫 판, 실기기 4대 초록. GitHub 앱에서 승인`
- `가계부: 플레이 콘솔 첫 등록 필요 (15분) — 답안 준비됨, 상황판 링크`
- `습관: 크래시 없는 사용자 97.9% (기준 99.5%) — 배포 멈추기 승인 요청`
- `단어장: 조사 48점이라 안 만듦 — 대신 "수능 영단어 음성 퀴즈" 변형 제안`

## 7. 막히면

| 상황 | 누가 알아채나 | 무엇을 하나 |
|---|---|---|
| CI 빨강 | 담당 세션(PR 이벤트) | 고쳐서 푸시. 사람 없음 |
| 맥 미니 러너 오프라인 | device-lab 잡이 대기 → 하루 요약 | "러너 n시간 오프라인" — 주인이 전원 · 로그인 확인(Tailscale 로 원격 확인 가능) |
| 애플 심사 반려 | ship 요약 · 애플 메일 · 루틴 | 반려 조항 읽고 고침 → 새 출시 요청(다시 승인) |
| 구글 정책 경고 | 메일 · 루틴 | 같은 방식. **계정 경고는 즉시 알림** — 계정이 닫히면 모든 앱이 내려감 |
| 크래시 급증 | 출시 뒤 루틴(Crashlytics · Play vitals) | 멈추기 승인 요청 + 원인 고침 |
| Claude 사용량 한도 | 세션이 멈춤 | 하루 요약에 "한도 도달, 재개 시각" — 주간 한도가 자주 차면 동시에 도는 앱 수를 줄이거나 요금제 상향 |
| 정해진 시간 안에 못 끝남 | 담당 세션 | 첫 판 기능을 줄여 먼저 내는 안을 상황판에 |

## 8. 동시에 몇 개를 굴리나

**시작은 동시에 만드는 앱 1개, 한 달에 출시 1~2개.** 늘리는 조건:
- 앞선 앱이 반려 없이 나갔고, 하루 요약의 「주인 할 일」이 주 1건 이하로 유지됨
- Claude 주간 한도에 여유가 있음
- 출시된 앱의 유지보수(연 1회 SDK · targetSdk 올리기 등)가 공장 시간의 20% 를 넘지 않음

속도보다 계정이 먼저입니다. 애플은 2026-06 에 4.3(b)를 고쳐 "비슷한 앱 반복 제출은 개발자 프로그램에서
제외될 수 있다" 고 적었고, 구글은 정지된 계정과 **연결된 계정까지** 닫습니다. AI 로 만든 앱이 쏟아지면서
(2026년 신규 제출 84% 증가) 심사는 더 깐깐해졌습니다. 자세한 것은 [MONEY.md](MONEY.md) 5절.
