# 세션 통신 — 여러 Claude 가 어떻게 한 공장으로 일하나

MyBody 의 병목은 **전달**이었습니다([LESSONS.md](LESSONS.md)): 클라우드 세션과 노트북 세션이 문서로 편지를
주고받고, 주인이 "15번 해줘" 를 날랐습니다. 이 문서는 그 자리를 무엇으로 채우는지 — 어떤 말은 어떤 통로로
가고, 무엇은 절대 사람을 거치지 않는지 — 를 정합니다. 사실관계는 2026-09-24 Claude Code 공식 문서 기준입니다.

project」로 기존 세션을 프로젝트에 넣습니다.

## 2. 통로 — 어떤 말은 어디로 가나

```
 주인(폰) ──주제·지시──▶ 공장장 ──스레드 열기──▶ 담당 스레드 ──PR·workflow_dispatch──▶ GitHub
    ▲                       ▲                       ▲  │                                   │
    │ 하루 요약(푸시)        │ 보고                   │  │ SendMessage(즉석)                  │ 잡 배정
    │ 승인 요청(GitHub 앱)   │                       │  ▼                                   ▼
  루틴 ◀──────────────── 프로젝트 기억 ◀── 스레드   mac-lab ◀──(같은 기기)──▶ 러너(맥 미니) ──▶ lab-results · 커밋 상태
```

| 말 | 보내는 쪽 → 받는 쪽 | 통로 | 왜 이 통로 |
|---|---|---|---|
| 새 주제 · "멈춰" · 방향 바꾸기 | 주인 → 공장장/스레드 | Claude 앱의 프로젝트 대화(공장장이 스레드로 라우팅) 또는 스레드에 직접 | 폰에서 되고, 공장장이 어느 스레드인지 알아서 찾음 |
| 정해진 기기 작업(시험 · 빌드 · 스크린샷) | 스레드 → 러너 | `gh workflow run device-lab.yml -f app=… -f ref=…` | 큐잉 · 재시도 · 로그 · 산출물이 공짜. 맥 미니가 꺼져 있어도 잡이 기다림 |
| 기기 작업의 **결과** | 러너 → 스레드 | ① 결과 파일을 `lab-results` 브랜치 `<앱>/<실행번호>/` 에 푸시 ② PR 의 head 커밋에 **커밋 상태**(`lab/ios` · `lab/android`) | ②가 PR 체크 이벤트가 되어 **스레드를 깨움**(PR 구독). ①은 스레드가 `git fetch` 로 읽음. "N 끝" 규약이 필요 없음 |
| CI 결과 · 리뷰 댓글 | GitHub → 스레드 | PR 구독(auto-fix). 스레드가 열었으면 자동 | 빨간 CI 를 스레드가 이벤트로 받아 고침 |
| 즉석 기기 일("지금 아이폰에서 알림 오는지 봐 줘") | 스레드 → mac-lab | `SendMessage` (Anthropic 서버 → 맥 미니의 Remote Control 연결) | 워크플로를 만들기엔 일회성. **정해진 일이 되면 워크플로로 승격** |
| 즉석 일의 답 | mac-lab → 스레드 | 같은 통로로 회신 (보낸 쪽이 Remote Control 이름을 갖고 있어야 답장 주소가 붙음) | |
| 결정 · 함정 · 규칙 변경 | 어느 스레드 → 모든 스레드 | **프로젝트 기억**(`MEMORY.md`, 공장장에게 "기억해 둬") · 규칙이면 저장소 `CLAUDE.md` PR | 새 스레드가 시작할 때 읽음. 대화 기록은 스레드 사이에 안 넘어감 |
| 단계 바뀜 · 막힘 · 주인 할 일 | 스레드 → 주인 | 스레드가 공장장에게 보고(Projects 가 함) + GitHub 이슈 `[상황판] <앱>` 본문 갱신 | Overview 「Waiting on you」가 실시간, 이슈는 폰 GitHub 앱에서도 보이고 프로젝트가 없어도 남음 |
| 하루 요약 · 긴급(계정 경고 · 크래시 급증) | 루틴 → 주인 | 루틴의 **푸시 알림**(새 세션 루틴에 push/email 설정) | 하루 한 번 + 급한 것만. 세션이 아무 때나 울리지 않음 |
| 출시 승인 | ship 워크플로 → 주인 | GitHub 배포 검토 알림(GitHub 앱) | 승인 버튼 = 열쇠 해제. Claude 는 못 누름 |
| 심사 결과 · 정책 메일 | 애플/구글 → 루틴 | Gmail 커넥터를 **루틴에만** 붙임 | 스레드마다 메일함을 열 필요 없음 |
| 주인이 맥 미니 화면을 보고 싶을 때 | 주인 → mac-lab | Claude 앱 세션 목록의 `mac-lab` (Remote Control) | 폰에서 로컬 세션을 그대로 조종 |

**규칙 셋**
1. **정해진 일은 워크플로, 즉석 일만 메시지.** 메시지는 큐도 재시도도 산출물 보관도 없습니다. 같은 즉석 일을 두 번
   보내게 되면 그날 워크플로 입력으로 만듭니다.
2. **결과는 파일과 상태로, 말로 하지 않는다.** 러너의 결과는 `summary.json` + 스크린샷 + 커밋 상태. 세션 간 메시지에
   시험 결과를 붙여 넣지 않습니다(길이 제한 · 유실).
3. **사람은 통로가 아니다.** 주인이 세션 A 의 말을 세션 B 에 옮겨야 하는 설계가 나오면 그 설계가 틀린 것입니다.

## 3. 왜 MyBody 의 SendMessage 는 승인에 걸렸나 — 그리고 고치는 법

MyBody 우편함 첫 줄: "SendMessage 는 클라우드 쪽에서 승인이 걸리니 쓰지 마세요." 원인은 **받는 세션의 기본 규칙**입니다
([문서](https://code.claude.com/docs/en/cross-session-messaging#control-inbound-messages)):

- 받는 세션이 **권한을 묻는 모드**(default · auto · acceptEdits)면 → 메시지를 그냥 전달. 보낸 쪽이 bypass 모드일 때만 보류.
- 받는 세션이 **bypassPermissions**(`--dangerously-skip-permissions`)면 → **모든 메시지를 보류**하고 승인 창을 띄움.
  보류된 메시지는 5분(`dialogExpiry`) 지나면 버려집니다.

노트북 세션이 bypass 로 돌고 있었거나, 양쪽 모드 조합이 그 칸에 걸렸을 가능성이 큽니다. 공장에서는:

```jsonc
// 맥 미니 lab 사용자의 ~/.claude/settings.json  (mac-lab 과 러너가 띄우는 모든 세션에 적용)
{
  "crossSessionInbound": "accept",     // 내 다른 세션의 메시지를 승인 없이 받음
  "dialogExpiry": "never",             // 그래도 보류되면 버리지 말고 둠
  "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "0" }
}
```
- mac-lab 은 `--permission-mode auto` 로 띄웁니다(bypass 아님). auto 는 "묻는 모드" 로 분류됩니다.
- 메시지는 **주인 승인이 아닙니다.** 받는 Claude 는 "다른 세션이 보냈다" 를 알고, 설정 · CLAUDE.md 를 바꾸라는
  요청은 따르지 않습니다. 훅 · 권한 규칙은 그대로 적용됩니다. 그러니 `accept` 로 열어도 스토어 제출 같은 것은 못 시킵니다.
- 맥 미니가 꺼져 있으면 메시지는 **다시 켜질 때 도착**합니다(보낸 쪽에 그렇게 알려 줌). 급한 일에는 맞지 않으니
  긴급은 루틴 알림 → 주인으로.
- 클라우드 → 맥 미니 메시지는 mac-lab 이 Remote Control 로 연결돼 있을 때만 목록에 보입니다. mac-lab 은 tmux 안에서
  상주하고, 서버가 멈추면 약 4시간 안에 `claude remote-control` 을 다시 띄우면 같은 세션이 돌아옵니다.

## 4. 메시지 · 결과의 모양 (자유 형식 금지)

MyBody 의 우편함은 60개 체크박스가 자유 문장이었고, 보고도 자유 문장이라 어느 것이 됐는지 다시 읽어야 했습니다.
공장은 모양을 정해 둡니다.

### 4-1. 워크플로 입력 (스레드 → 러너)
```
gh workflow run device-lab.yml -f app=habit -f ref=<커밋> -f suite=smoke|full|explore
```
스레드가 PR 을 열어 두고, 그 head 커밋을 `ref` 로 줍니다. 그래야 결과 상태가 PR 에 붙습니다.

### 4-2. 러너 결과 (`lab-results/<앱>/<실행번호>/`)
```
summary.json   { app, ref, suite, started, finished, devices:[{name, os, flows:{first-run:"pass", paywall:"fail"}, startupMs, shots:[…]}], blocking:true|false }
report.md      사람이 읽는 판 — 실패한 흐름은 재현 순서 · 스크린샷 파일명 · 로그 마지막 40줄
shots/         <기기>-<흐름>-<단계>.png  (라이트 · 다크 · 큰 글꼴)
```
그리고 head 커밋에 커밋 상태 `lab/<플랫폼>` = success/failure + 설명 한 줄 + `lab-results` 링크.

### 4-3. 세션 간 메시지 (즉석 일)
```
[요청] habit · 아이폰12에서 예약 알림 2분 뒤 도착하는지 (빌드: lab-results/habit/412 의 ipa)
[결과 놓을 곳] lab-results/habit/412-adhoc/
[급함] 아니오 — 오늘 안
```
답장도 세 줄: `[결과] 도착 안 함 · 스크린샷 …/adhoc/notif.png · 콘솔에 "UNUserNotificationCenter … not authorized"`.

### 4-4. 스레드 → 공장장 보고 (Projects 가 자동으로 받지만 마지막 메시지의 첫 줄을 이렇게)
```
습관 · S5 검증 끝 → S6 · 실기기 4대 초록 · 주인 할 일: 없음
```

### 4-5. 상황판 이슈 본문
[seed/CLAUDE.md](seed/CLAUDE.md) §5 의 5줄 형식. 댓글을 쌓지 않고 본문을 고쳐 씁니다.

## 5. 지식이 흐르는 곳 — 무엇을 어디에 남기나

| 종류 | 예 | 두는 곳 | 누가 읽나 |
|---|---|---|---|
| **규칙** (항상 지킬 것) | 열쇠 안 열기 · 시험 안 끄기 · 보고 형식 | `CLAUDE.md` (저장소) · 프로젝트 지침(16,000자, 요약판) | 모든 스레드 시작 시 |
| **결정** (이 공장이 정한 것) | "결제는 RevenueCat" · "구글 조직 계정으로 전환 중" | **프로젝트 기억**(`MEMORY.md`) — 공장장에게 "기억해 둬" | 모든 새 스레드 |
| **함정** (한 번 겪은 것) | "Maestro 는 실제 아이폰 안 됨" · "shared_preferences 는 privacy manifest 필요" | 프로젝트 기억 + 굳으면 `docs/factory/LESSONS.md` PR | 새 스레드 · 다음 앱 |
| **산출물** | 조사 · 기획 · 문안 · 시험 결과 | 저장소 `portfolio/<앱>/` · `lab-results` 브랜치 | 그 앱의 스레드 · 루틴 |
| **상태** | 지금 어느 단계 · 막힘 | Overview + `[상황판]` 이슈 | 주인 · 루틴 |
| 대화 기록 | | **안 넘어감.** 스레드는 서로의 대화를 못 봅니다 | — |

원칙: **다른 스레드가 알아야 할 것을 대화에만 남기면 사라진 것과 같습니다.** 기억 · 저장소 · 이슈 중 한 곳에 씁니다.

## 6. 한 스레드 안의 병렬 — 서브에이전트와 팀

- **서브에이전트**(`.claude/agents/`): 조사 · 비평 · 심사관 · 탐색. 결과만 돌아오고 문맥을 안 잡아먹습니다. 기본.
- **교차 검토**: MyBody 는 순차 5회였습니다. 공장은 정확성 · 문구 · 정책 검토 에이전트를 **동시에 백그라운드**로 띄우고
  세 결과를 합칩니다. 확인된 것만 고치고 "교차 검토에서 확인된 것 고침" 커밋.
- **에이전트 팀**(`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, 실험 기능): 팀원끼리 직접 대화하며 서로 반박하는 조사에
  좋지만 토큰이 크게 늘고, 대화형 세션에서만 팀이 만들어집니다. **첫 앱에서는 끄고**, 조사 단계에서 "경쟁 가설 토론"
  이 필요할 때만 켭니다. (켜 두면 이름 붙인 서브에이전트가 전부 팀원으로 떠서 의도치 않은 팀이 생깁니다.)

## 7. 동시성 · 충돌 · 한도

- 스레드는 **앱마다 하나**가 기본. 한 앱에 스레드 둘이면 같은 파일을 고칩니다. 큰 앱에서 나누려면 `apps/<앱>/lib/features/<기능>/`
  단위로 파일 소유를 가르고, 공장장에게 "이 앱은 스레드 둘, 파일 경계는 …" 이라고 기억시킵니다.
- `packages/` 를 고치는 일은 스레드 하나만. 모든 앱 CI 가 그 PR 에서 돕니다.
- 러너는 맥 미니 하나 · 동시 잡 1개. 잡이 밀리면 GitHub 이 줄을 세웁니다. 시험이 45분을 넘으면 `suite=smoke` 로 나누고
  `full` 은 밤에.
- 한도: 프로젝트 스레드는 **하루 200개**, 사용량은 구독 한도를 공유하고 **한도에 닿으면 스레드가 스스로 기다렸다 이어 감**.
  Pro 에서는 프로젝트 하나로도 한도에 자주 닿습니다 → Max. 루틴은 하루 실행 수 상한이 따로 있음(claude.ai/code/routines 에서 확인).
- 스레드 샌드박스는 턴 사이에 멈추고, 못 살리면 새 클론에서 이어 갑니다 → **커밋 안 한 것은 사라질 수 있음.** 스레드 규칙:
  30분마다, 그리고 기기 시험을 기다리기 전에 커밋 · 푸시.
- 스레드 모델 · 노력: 새 프로젝트 기본은 Opus · high. 조사 · 문안 · 검토 서브에이전트는 Sonnet 으로 내려도 됩니다
  (프로젝트 설정 > General). 코드 스레드는 그대로.

## 8. 맥 미니를 띄우는 한 줄과 상주 규칙

```bash
# lab 사용자로 로그인된 상태. 러너는 svc.sh 서비스로 이미 돎.
tmux new -d -s lab 'cd ~/lab/app-factory && claude remote-control --name mac-lab --spawn worktree --permission-mode auto'
```
- `--spawn worktree`: 폰에서 세션을 하나 더 열어도 서로 파일을 안 망칩니다.
- mac-lab 은 **시험 기기 목록에 있는 기기만** 만집니다(QUALITY.md 기기표). 훅이 시스템 앱 삭제 · 스토어 API 를 막습니다.
- mac-lab 에도 저장소의 `.claude/`(훅 · 권한 · 에이전트)가 그대로 적용됩니다 — 같은 저장소를 클론했으니까.
- 재부팅 뒤: 자동 로그인 → LaunchAgent 가 러너를 올림 → `tmux` 는 로그인 항목 스크립트로 위 한 줄을 다시 실행.
  (4시간 안이면 `claude remote-control` 만 다시 쳐도 옛 세션이 돌아옵니다.)
- (선택) **Telegram 채널**: `claude --channels plugin:telegram@…` 로 띄우면 주인이 텔레그램으로 mac-lab 에 말을 걸고
  답을 받습니다. 채널은 로컬 CLI 세션에서만 되고 Pro/Max 개인 계정은 바로 됩니다. Claude 앱이 있으니 필수는 아닙니다.

## 9. 첫 주에 이 설계를 검증하는 순서

1. 프로젝트 만들기(저장소 `app-factory` 하나만 넣기 — 하나여야 저장소의 훅 · 권한 규칙이 스레드에 적용됩니다) →
   프로젝트 지침에 seed/CLAUDE.md 의 §2 · §5 · §6 요약을 넣기.
2. 스레드 하나로 `/new-app` 을 끝까지(조사 → 기획) 돌려 보고, 보고 형식이 맞는지.
3. 러너: `device-lab.yml` 을 `suite=smoke` 로 한 번 → 커밋 상태가 PR 에 붙고 스레드가 깨어나는지.
4. mac-lab: 스레드에서 세 줄 메시지를 보내 답이 오는지(승인 창 없이). 안 오면 §3 설정 확인.
5. 루틴: 하루 요약을 만들고 「Run now」 → 폰에 푸시가 오는지.
6. 출시 창구: `ship.yml` 을 더미 입력으로 실행 → GitHub 앱에 승인 요청이 오는지 → Reject.

여섯 개가 다 되면 그때부터 주인은 주제만 던집니다.
