# 더 좋은 앱 · 수익화 — 조사 결과와 공장의 규칙

2026-09-24 에 확인한 것입니다. [V] = 공식 문서를 직접 읽음 · [S] = 2차 자료나 검색 요약 · [?] = 확인 못 함.
법률 · 세무 부분은 자문이 아닙니다 — 첫 매출 전에 세무사 한 번.

---

## 0. 세 줄 결론

1. **돈은 앱 개수가 아니라 살아남는 앱 하나에서 나옵니다.** 구독 앱의 17.3% 만 2년 안에 월 $1K 에 닿고, 매출의
   95% 는 상위 10% 앱이 가져갑니다[S]. 공장의 목적은 "많이" 가 아니라 **빨리 만들고 빨리 접어서** 그 하나를 찾는 것입니다.
2. **계정이 자산입니다.** 애플은 2026-06 에 "비슷한 앱 반복 제출은 개발자 프로그램에서 제외될 수 있다" 고 못박았고[V],
   구글은 정지된 계정과 **연결된 계정**까지 닫습니다[S]. 템플릿 티가 나는 앱을 여러 개 내는 순간 공장이 끝납니다.
3. **한국 1인 개발자의 기본형 = 서버 없는 유틸리티/습관/기록 앱 + 연간 구독(체험 7~14일) + 한국어 · 한국 제도에
   맞춘 차별점.** 광고는 DAU 가 수천 이상일 때만 의미가 있고, AI 기능은 원가가 있으니 유료 안에만.

## 1. 어떤 앱을 만들까 — 주제 고르기

`market-researcher` 의 점수표([seed/.claude/agents/market-researcher.md](seed/.claude/agents/market-researcher.md))가
기준입니다. 점수 뒤에 있는 생각:

**고르는 것**
- **반복 행동이 있는 것** — 매일 · 매주 켤 이유(기록 · 습관 · 알림 · 계산). 구독은 반복 사용에서만 성립합니다.
- **서버 없이 첫 판이 되는 것** — 기기 저장 + (선택) iCloud/구글 드라이브 백업. 서버는 운영비 · 개인정보 의무 ·
  장애 · 계정 삭제 페이지를 끌고 옵니다. MyBody 는 서버 때문에 오라클 VM · Tailscale · 동의 판 · 비밀번호 찾기까지 필요했습니다.
- **한국이 이점인 것** — 한국 제도(연말정산 · 청약 · 육아휴직 · 학교 일정) · 한국 서비스(카카오 · 배민 · 당근 ·
  인바디) · 한글(초성 검색 · 한/영 오타) · 한국식 단위(평 · 근 · 만원). 미국 앱을 번역만 한 것은 미국 앱이 이깁니다.
- **상위 앱 불만이 크고 우리가 풀 수 있는 것** — "광고가 너무 많다" "구독 강요" "동기화 안 됨" "영어뿐".
  별점 1~3 리뷰가 기획의 원료입니다.

**피하는 것**
- 애플 4.3(b) 가 이름을 박아 둔 포화 분류: **데이팅 · 손전등 · 효과음 · 벽지 · 단순 타이머 · 운세**[V] — 의미 있게
  다르지 않으면 반려.
- 건강 진단 · 금융 조언 · 아동 · 사행성 — 심사 · 법 · 책임이 무겁습니다. (몸 관리 앱은 되지만 "진단" 문구는 금지)
- 남의 데이터 · 남의 API 에 통째로 기대는 것 — 끊기면 앱이 죽습니다.
- 첫 판에 기능 10개 — 3~5개로 냅니다. 나머지는 지표가 말해 줍니다.

**주제 대기열의 원천**: 주인이 던진 것 + 조사 중 발견한 변형 + 출시 앱 리뷰에서 나온 "이런 것도 있었으면".

## 2. 수익 모델 고르기

| 모델 | 맞는 앱 | 장점 | 함정 |
|---|---|---|---|
| **연간 구독 + 무료 체험** (기본형) | 반복 사용 · 계속 쌓이는 데이터 | 벤치마크가 가장 좋음. 연간이 월간보다 갱신 훨씬 높음[S] | 체험 뒤 요금이 언제 얼마 나가는지 명확해야(3.1.2 · 한국 전자상거래법) |
| **1회 구매 (평생)** | 도구 · 계산기 · 변환기 | 한국 사용자 거부감 낮음 · 환불 적음 | 성장 상한. 갱신 매출 없음 |
| **하이브리드**(무료 + 구독 + 평생권) | 대부분 | 평생권이 "구독 싫은 사람" 을 받음 | 결제 벽이 복잡해지면 전환 떨어짐. 실제로 진짜 하이브리드는 앱의 ~10%[S] |
| **광고** | DAU 수천 이상 · 세션 짧고 잦음 | 결제 장벽 0 | 한국 인터스티셜 eCPM 약 $10~11[S, 게임 위주 자료] → DAU 1,000 · 하루 2회 노출이면 **월 $600 안팎**. 배너는 그보다 훨씬 낮음. UMP · ATT 동의 필요 |
| 무료 | 포트폴리오 · 평판 · 다른 앱 유입 | 심사 · 세금 단순 | 돈 0 |

**하드 페이월(체험 없이 결제 벽) vs 프리미엄**[S, RevenueCat 2026]: 설치→유료 35일 기준 **10.7% vs 2.1%**, 1년 유지는
27% vs 28% 로 비슷. 온보딩이 가치를 설득할 수 있는 앱이면 하드 페이월이 돈은 더 법니다. 대신 리뷰가 거칠어지고
설치 수가 줄어 ASO 에 불리합니다. **공장 기본은 "가치를 한 번 맛보게 한 뒤 벽" + 체험**, 데이터가 쌓이면 A/B.

공장 규칙:
- 체험은 **7일 기본**, 앱이 하루 안에 가치를 못 보여 주면 14일. 애플은 구독 최소 7일[V].
- 결제 벽은 온보딩 끝, **핵심 가치를 한 번 본 뒤**. 첫 실행 당일에 체험을 못 시키면 대부분 다시 안 옵니다.
- 가격 초안은 한국 스토어에서 **₩4,900/월 · ₩29,000/년 · ₩49,000 평생** 언저리에서 시작해 경쟁 앱과 대조. 연간을 앞에.
- 결제 화면 필수 요소(애플 3.1.2[V]): 가격 · 기간 · 자동 갱신 · 해지 방법 · 약관 · 개인정보 · **복원 버튼**.
- 한국 전자상거래법(2025-02-14 시행)[S]: 무료→유료 전환 · 가격 인상 **30일 전 명시적 동의**. 스토어가 결제를
  대행하는 체험에 어떻게 적용되는지는 불명확[?] — 체험 시작 화면에 "n일 뒤 ₩x 결제" 를 크게, 만료 전 알림 한 번.
- 환불: 한국 청약철회 7일[S]. 애플 · 구글이 처리하지만 리뷰에 남습니다.

## 5. 정책 위험 — 계정을 지키는 규칙

**애플**[V, 2026-06-08 개정]
- **4.3(a)** 같은 앱을 번들 ID 만 바꿔 여러 개 금지. 변형은 인앱결제로.
- **4.3(b)** "이미 널리 있는 것과 구분 안 되는 앱" 반려. 개선 · 갱신 · 사용자 유치가 없으면 **삭제될 수 있음**.
  "반복 제출은 **개발자 프로그램 제외**로 이어질 수 있음".
- **4.2 · 4.2.6** 최소 기능 · 템플릿/앱 생성 서비스로 만든 앱은 콘텐츠 제공자 본인이 내야.
- **5.1.2(i)** 제3자 AI 에 개인 데이터를 보내면 **명시적 동의**.
- AI 로 만든 앱 자체를 금지하는 조항은 없음. 다만 2026 상반기 신규 제출이 84% 늘어(약 56만 개) 심사가 느려지고 깐깐해짐[S].

**구글**[S]
- 비슷한 콘텐츠 · 경험의 앱 여러 개 = 스팸. 템플릿 앱을 운영자가 대신 올리는 것 금지.
- **계정 정지는 연결된 계정까지** — 같은 결제수단 · 주소 · 전화 · IP 로 엮임. 정지 뒤 새 계정은 닫힘.
- 2026-07-15 개인정보 정책이 제3자 AI 통합을 명시.

**공장 규칙**(seed/CLAUDE.md §2 에 있음): 같은 앱 이름만 바꿔 내기 금지 · 공통 패키지는 쓰되 화면과 핵심 기능은
앱마다 다르게 · `store-reviewer` 가 `apps/*` 끼리 겹침을 검사 · 반려 사유는 계정 단위 위험이면 즉시 알림.

## 6. 광고를 붙일 때

- 조건: DAU 수천 이상, 세션이 짧고 잦음, 유료 전환이 안 되는 사용자층. 그 전에는 **결제 벽과 리뷰 점수를 해칩니다.**

- 수익 어림: ARPDAU = (DAU 당 노출 × eCPM) / 1000. 한국 인터스티셜 eCPM 약 $10[S] · 배너는 미확인.
- 리워드 광고(보상형)는 "기능 잠깐 열기" 에 맞고 반감이 제일 적습니다.

| **30일** | D7 ≥ 15% 또는 체험 시작 ≥ 6% | D1 ≥ 25% 인데 D7 < 10% (첫 경험은 좋은데 안 돌아옴 → 알림 · 반복 행동 손보기) | D1 < 15% 이고 리뷰에 방향성 없음 |
| **60일** | 체험→유료 ≥ 25% 또는 MRR 상승 추세 | 체험 시작은 되는데 전환 < 15% (가격 · 체험 길이 · 벽 위치 A/B) | 설치가 안 늘고 ASO 손봐도 노출 안 늘음 |
| **90일** | MRR ≥ ₩300,000 이고 오르는 중 → **다음 기능 투자 · 광고 소액 실험 제안** | MRR 은 있는데 정체 → 가격 · 연간 비중 · 평생권 | MRR < ₩100,000 이고 90일 동안 안 오름 |

기준은 위 벤치마크(업계 D1 25%, D7 11~13%, D30 5~7%[S, 낮은 신뢰])에서 잡은 것이고 **정답이 아니라 시작점**입니다.
세 앱쯤 지나면 우리 숫자로 바꿉니다. "정리" 는 삭제가 아닙니다 — 연 1회 SDK 올리기만 하고 둡니다(내리면 남은 구독자와 평점이 날아감).

## 10. AI 기능을 넣을 때의 원가

앱 안에서 Claude 를 부르면(서버 프록시 필수 · 앱에 열쇠 금지) 사용자 한 명당 원가가 생깁니다. 2026-09 요금:

| 모델 | 입력 $/1M 토큰 | 출력 $/1M | 맞는 곳 |
|---|---|---|---|
| Haiku 4.5 | $1 | $5 | 분류 · 짧은 요약 · 문구 다듬기 |
| Sonnet 5 | $2 | $10 | 사진 판독 · 긴 글 · 대화 |
| Opus 5.5 | $4 | $20 | 필요할 때만 |

프롬프트 캐싱(고정 시스템 프롬프트를 캐시 읽기로 — 입력의 10% 값)과 배치 API(50% 할인, 실시간 아닐 때)를 쓰면 크게 줄어듭니다.
어림: 사진 한 장 판독(입력 ~2K 토큰 · 출력 ~300) 을 Sonnet 5 로 하면 **약 $0.007** → 월 100장 쓰는 사용자 = $0.7.
월 ₩4,900 구독이면 남지만 무료 사용자에게 무제한으로 열면 적자입니다. **AI 기능은 유료 안에, 무료는 하루 n회.**
(MyBody 의 사진 판독이 정확히 이 구조 — 서버 프록시 + 사용자가 직접 켬.)
