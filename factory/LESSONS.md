# MyBody 회고 — 무엇이 느렸고, 공장은 무엇을 바꾸는가

MyBody 는 처음이었습니다. 되긴 됐지만 **사람이 버스 노릇을 했고, 세션 둘이 문서로 편지를 주고받았고,
출시 결과물을 손으로 옮겼습니다.** 이 문서는 그 기록을 숫자로 뽑고, 각 숫자를 공장의 설계 결정으로
바꿉니다. 근거는 전부 이 저장소 안에 있습니다(커밋 로그 · `docs/LOCAL-TASKS.md` · `docs/LOCAL-REPORT.md`).

## 2. 불편했던 것 → 공장의 결정

### 2-1. 세션 사이의 통신

| MyBody 에서 | 왜 그랬나 | 공장 |
|---|---|---|
| **문서 우편함**(LOCAL-TASKS/REPORT.md)으로 편지 | SendMessage 를 시도했으나 클라우드 쪽에서 **승인 대기**에 걸려 포기 ("SendMessage 는 승인이 걸리니 쓰지 마세요") | 받는 쪽 세션 설정에 `crossSessionInbound: accept` 를 넣으면 승인 없이 들어옵니다(기본값은 두 세션의 권한 모드 조합으로 정해져서 자주 걸립니다). 그래도 메시지는 **급한 즉석 일**에만. 정해진 일은 GitHub 워크플로로 — [SESSIONS.md](SESSIONS.md) |
| **주인이 버스** — "15번 해줘" 를 사람이 전달 | 클라우드 세션은 노트북을 못 깨움 | 맥 미니를 **GitHub self-hosted 러너**로. 클라우드 세션이 워크플로를 실행하면 맥 미니가 알아서 받아 돌리고 결과를 올림. 사람 없음 |
| 보고를 **커밋**으로 (코드 브랜치에 보고 파일이 섞임) | 다른 통로가 없었음 | 결과는 `lab-results` 브랜치 또는 워크플로 요약으로. 코드 브랜치에 보고를 섞지 않음 |
| "끝나면 'N 끝' 이라고 적어 주세요" 를 12번 반복 | 완료 신호 규약이 없음 | 워크플로는 끝나면 GitHub 이벤트로 세션을 깨움(PR 구독) — 신호 규약이 필요 없음 |
| 노트북에 playwright 없음 → 시험 하나를 못 돌림 | 두 기기의 도구가 다름 | 실험실 도구 설치는 스크립트 하나([SETUP.md](SETUP.md) 4-2) · CI 와 같은 Flutter 판 고정 |

### 2-2. 사람이 손으로 한 것

| MyBody 에서 | 공장 |
|---|---|
| 60개 확인 항목을 노트북 세션이 **에뮬레이터를 손으로 눌러** 확인 | Maestro 흐름 시험(정해진 것) + `qa-explorer`(탐색) — 둘 다 러너가 돌림. 사람이 누르는 항목은 0이 목표 |
| 한글 검색을 못 쳐 봄 (에뮬레이터에 한글 입력기 없음) | 실기기(안드로이드 폰)에서 시험. 입력기 없이도 시험 코드가 문자열을 직접 넣음 |
| WHPX 꺼져 있어 에뮬레이터 안 뜸 (관리자 권한) | 기기 세팅 체크리스트에 미리 ([SETUP.md](SETUP.md) 6절). 주 실험실은 맥 미니(하이퍼바이저 문제 없음) |
| 서버를 **11번** 다시 띄움 | 서버가 노트북에 살고 앱 배포와 결합 → 서버는 VM 에 두고 배포는 워크플로로. 앱 · 서버 호환(동의 판 등)은 **서버가 옛 판을 계속 받는 규칙**으로 순서 의존을 없앰 |
| 릴리스 AAB 를 `gh release download` 로 받아 바탕화면 폴더에 넣고, **pepk.cmd 더블클릭**, 콘솔에 손으로 업로드 | 새 앱은 처음부터 플레이 앱 서명(pepk 없음). 업로드는 워크플로. 첫 AAB 한 번만 콘솔 |
| 등록정보 문구를 콘솔에 손으로 치고, 실제 입력값을 다시 문서에 적음 | 문안은 저장소가 원본, ship 워크플로가 API 로 올림. 콘솔에서만 되는 칸은 `console-answers.md` 로 복사-붙여넣기 |
| 심사용 계정을 노트북에서 만들고 비밀번호를 리셋 | 심사 계정은 S6 스크립트가 만들고 심사 메모에 자동 기입 |

### 2-3. 결과물이 틀렸는데 빌드는 초록

| 실제로 있었던 일 | 공장의 검사 ([QUALITY.md](QUALITY.md) L5) |
|---|---|
| `find \| head -1` 이 서명 전 중간 AAB 를 집어 **서명 안 된 파일**이 릴리스에 | 결과물 경로 고정 + `META-INF` 서명 존재 + 지문 = 업로드 열쇠 확인 |
| 불러 쓰는 워크플로에 `secrets: inherit` 빠져 **디버그 열쇠**로 서명된 앱이 배포로 | 서명 지문 검사가 디버그 지문이면 멈춤 |
| iOS 알림 초기화에 안드로이드 설정만 있어 **아이폰 알림 전부 꺼짐** — 예외를 삼킴 | 삼킨 예외 금지(규칙) + 실기기 알림 도착 시험 |
| 테마 색이 비어 흰 글자 → 카드 제목이 안 보여 "셋 다 같은 카드" 로 보임 | 골든 스크린샷 라이트/다크 + 대비 검사 |
| 시험이 플랫폼 플러그인 `await` 에서 **영영 멈춤** (예외도 timeout 도 없음) | 부팅은 플러그인을 기다리지 않음 + 시험용 가짜 플러그인 |
| 판독 신뢰도 점수가 틀린 값에 더 높은 점수 | "그럴듯한 틀린 값" 은 값끼리 검산으로만 잡힘 — 도메인 규칙으로 |

### 2-4. 판 · 출시 · 상태의 진실이 둘

| MyBody 에서 | 공장 |
|---|---|
| 클라우드와 노트북이 각자 "다음 판은 0.2.x" 를 정함 → 어긋남 | 판은 **태그 하나**(`<앱>-v1.2.3`)가 진실. 빌드 번호 = 커밋 수. 누구도 손으로 안 정함 |
| 릴리스 폴더 이름 v0.2.4, 안의 versionName 0.2.3 | 결과물 검사에서 이름 · 매니페스트 · 태그 셋을 대조 |
| 주인 폰 · 노트북 폴더 · 저장소 · 콘솔에 문안이 각각 | 원본은 저장소 `portfolio/<앱>/store/` 하나. 나머지는 거기서 나감 |
| 세션 상태를 알려면 우편함 문서를 읽어야 | Projects 의 Overview(「Waiting on you」)가 상황판. 없으면 GitHub 이슈 한 개 |

### 2-5. 잘 됐던 것 — 그대로 가져감

- **교차 검토** — 5차까지 갔지만 매번 실제 버그를 잡았습니다(요일 차이 · 하루치 기준 · 유지 구간 · 오타 고치기 빈틈).
  공장에서는 **순차 5회** 대신 관점이 다른 검토 에이전트를 **병렬**로 돌리고, 확인된 것만 고칩니다.
- **차이 검사(difftest)** — JS 와 Dart 가 같은 답을 내는지 글자 단위로. 이식 · 리팩터링에 계속 씁니다.
- **preflight 한 줄** — 검사 목록을 한 곳에 · 막음/확인 구분 · 왜 이 검사가 있는지 한 줄. 공장 CI 의 골격입니다.
- **결과물을 열어서 확인** — 이미 있던 매니페스트 검사(인터넷 권한)를 서명 · 판 · 권한 전체로 넓힙니다.
- **맥 없이 iOS 서명** (`tools/asc.js`) — 애플 API 로 인증서 · 프로파일. 공장에서는 인증서를 한 번 만들어
  보관하고 프로파일만 앱별로.
- **한국어 커밋 메시지에 "왜"** — 몇 달 뒤 다른 세션이 읽어도 이유가 보입니다.
- **우편함이라는 발상 자체** — 세션 사이에 "무엇을 확인해 달라" 를 구조화한 것. 공장에서는 사람이 전달하지
  않게 바꿀 뿐, 워크플로 입력과 결과 형식으로 이어집니다.

> 사람이 날랐습니다. 공장은 그 세 전달을 GitHub 이벤트 · 러너 · API 로 바꾸고, 사람에게는 **승인 버튼 하나**만 남깁니다.
