# 앱 공장 — Claude 가 지키는 규칙

이 저장소는 앱을 만드는 공장입니다. 주인이 주제를 한 줄 던지면 Claude 가 조사 · 기획 ·
설계 · 구현 · 시험 · 출시 준비까지 하고, 주인이 **출시 승인 버튼 하나**를 누르면 스토어로
나갑니다. 주인은 보고만 받습니다.

**주인의 시간이 이 공장에서 가장 비싼 자원입니다.** 주인에게 묻는 것은 주인만 할 수 있는
일(§6)뿐이고, 나머지는 Claude 가 정하고, 정한 이유를 보고에 한 줄로 남깁니다.

설계 배경 · 기기 세팅 · 수익화 조사는 `docs/factory/` 에 있습니다(MyBody 저장소
`factory/` 에서 옮겨 온 것).

---

## 1. 단계 — 무엇이 끝나야 다음으로 가는가

앱 하나는 `apps/<이름>/`(코드)와 `portfolio/<이름>/`(문서)를 갖습니다. 단계마다 산출물이
있고, **끝 조건을 못 채우면 다음 단계로 가지 않습니다.**

| 단계 | 산출물 (`portfolio/<이름>/`) | 끝 조건 |
|---|---|---|
| S1 조사 | `research.md` | 경쟁 앱 10개 이상 · 그 앱들의 별점 1~3 리뷰에서 불만 유형 묶음 · 키워드 후보 20개 · 수익 모델 가설 · `score.md` 점수 **60점 이상** (미만이면 멈추고 보고) |
| S2 기획 | `brief.md`(한 쪽) · `spec.md` | 핵심 반복 행동 **하나** · 첫 30초 흐름 · 화면 목록 · 저장 데이터와 가는 곳 · 결제 지점 · 측정 이벤트 · 정책 위험 목록 |
| S3 설계 | `design/` 시안 스크린샷 · 문구표 | 모든 화면의 빈 상태 · 오류 상태 · 로딩 상태까지 그려짐. `product-critic` 검토 통과 |
| S4 구현 | `apps/<이름>/` · PR 들 | 기능마다 PR · 시험 포함 · CI 초록 · 교차 검토(§3) |
| S5 검증 | `qa/<판>/` 보고 · 스크린샷 | `docs/factory/QUALITY.md` 의 L1~L5 전부 초록. 실기기 스크린샷이 보고에 붙음 |
| S6 출시 준비 | `store/` 문안 · 스크린샷 · 개인정보 답안 | TestFlight · 플레이 내부 테스트에 올라감 · `store-reviewer` 검토 통과 · 출시 요청(§5) 올림 |
| S7 출시 | — | **주인 승인 뒤에만.** 출시 창구의 ship 워크플로가 제출 · 배포 |
| S8 운영 | `metrics.md` | 30 · 60 · 90일째 계속/개선/정리 판정 (`docs/factory/MONEY.md` 「판정표」) |

S1 이 60점을 못 넘거나, S2 에서 정책 위험이 "높음" 이면 **만들지 않는 것이 결과**입니다.
만들지 않기로 한 것도 보고합니다 — 그것도 주인의 시간을 아낀 일입니다.

## 2. 절대 하지 않는 것

도구 단계에서도 막혀 있습니다(`.claude/hooks/guard.js`). 막혔다고 다른 모양으로 우회하지
않습니다 — 막힌 이유를 보고의 「주인 할 일」에 적습니다.

- **주인 승인 없이 스토어에 제출 · 프로덕션 배포하지 않습니다.** 스토어 API 는 GitHub
  워크플로에서만 부르고, 출시용 열쇠는 출시 창구 저장소(`app-factory-ship`)의 `store-production`
  환경에만 있습니다. 이 저장소의 워크플로 · 환경 설정은 고치지 않습니다.
- **서명 열쇠 · API 열쇠 파일을 열거나, 출력하거나, 옮기지 않습니다.** 로그에 비밀값을 찍지 않습니다.
- **시험을 끄거나 건너뛰거나 기대값을 바꿔서 초록을 만들지 않습니다.** 시험이 틀렸으면
  왜 틀렸는지 커밋 메시지에 적고 고칩니다.
- **돈을 쓰지 않습니다.** 광고 예산 · 유료 API 요금제 · 도메인 구매는 제안만 합니다.
- **남의 것을 쓰지 않습니다.** 상표 · 캐릭터 · 남의 앱 이름 · 출처 모를 그림과 글꼴.
- **사용자를 속이지 않습니다.** 가짜 리뷰 · 별점 유도 보상 · 숨은 구독 · 끄기 어려운
  자동 갱신 · 없는 기능 광고 · 동의 없는 추적.
- **앱 안에 API 열쇠를 넣지 않습니다.** 외부 AI · 유료 API 는 서버를 거칩니다.
- **같은 앱을 이름만 바꿔 여러 개 내지 않습니다.** (애플 4.3 · 구글 스팸 정책 —
  계정이 통째로 닫히면 공장이 끝납니다.)
- **주인 폰의 개인 데이터와 시스템 앱을 건드리지 않습니다.** 시험 기기에서는 우리 앱 패키지만 다룹니다.

## 3. 반드시 하는 것

**만든 것을 열어서 확인합니다.** 빌드가 초록이라는 것과 나온 결과물이 맞다는 것은 다른
이야기입니다. MyBody 에서 실제로 있었던 일:
- `find | head -1` 이 서명 전 중간 AAB 를 집어서 서명 안 된 파일이 릴리스에 올라감
- 불러 쓰는 워크플로에 `secrets: inherit` 가 빠져 **디버그 열쇠로 서명된 앱**이 배포로 나감 — 빌드는 끝까지 초록
- iOS 알림 초기화에 안드로이드 설정만 있어서 아이폰에서 알림이 전부 꺼짐 — 예외를 삼켜서 아무도 몰랐음

그래서 결과물마다: 서명 지문 · 번들 ID · 판 번호 · 권한 목록 · 크기를 **파일을 열어서** 확인하는
단계가 CI 에 있어야 하고, 없으면 먼저 만듭니다.

**교차 검토.** 기능 PR 은 머지 전에 서로 다른 관점의 검토 에이전트 둘 이상(정확성 ·
사용자 문구 · 정책 중 해당하는 것)을 돌리고, 확인된 것은 고치고, 커밋 메시지에
"교차 검토에서 확인된 것 고침" 으로 남깁니다.

**버그는 시험부터.** 버그를 고치면 그 버그를 다시 잡는 시험을 같은 커밋에 넣습니다.

**보고는 사실만.** 통과한 시험 수, 실패한 것은 출력 그대로, 확인 못 한 것은 "확인 못 함"
이라고 씁니다. 추정은 추정이라고 씁니다.

**예외를 삼키지 않습니다.** `catch (_) {}` 로 넘기면 폰에서 조용히 기능이 꺼집니다.
삼켜야 하면 왜인지 주석과 로그를 남깁니다.

## 4. 품질 바 (모든 앱 공통)

자세한 시험 체계와 기기표는 `docs/factory/QUALITY.md`. 최소선:

- 첫 화면 2초 안(중급 안드로이드 실기기 기준) · 오류 화면(회색 네모) 0 · 콘솔 오류 0
- 오프라인에서 켜지고, 망이 없으면 무엇이 안 되는지 말함
- 가장 작은 화면(iPhone SE · 360dp 폭)과 가장 큰 글꼴에서 글자가 잘리지 않음
- 라이트 · 다크 둘 다에서 글자가 보임 (MyBody: 테마 색이 비어 흰 글자가 안 보였음)
- 한국어 문구는 사람이 쓴 것처럼 — 번역투 · "~하십시오" · 영어 섞기 없이. 문구표 한 곳에서 관리
- 앱이 쓰는 글자가 글꼴에 다 있음 (없으면 네모 또는 몰래 인터넷에서 글꼴을 받음)
- 계정이 있으면 **앱 안에서 계정 삭제** · 개인정보처리방침 주소 · 문의 주소
- 구독이 있으면 결제 화면에 가격 · 기간 · 자동 갱신 · 해지 방법 · 약관 · 복원 버튼

## 5. 보고

주인은 폰으로 봅니다. **세 줄 안에 판단할 수 있게** 씁니다.

### 상황판
Projects 안이면 스레드의 마지막 보고 첫 줄이 공장장과 Overview 에 그대로 뜹니다 — 그 줄을 아래 첫 두 줄
(단계 · 주인 할 일)로 씁니다. 그와 별개로 앱마다 GitHub 이슈 하나(제목 `[상황판] <앱 이름>`, 라벨 `status`)를
두고 **단계가 바뀔 때** 맨 위 본문을 고쳐 씁니다(댓글을 쌓지 않음). 이슈는 폰 GitHub 앱에서도 보이고
프로젝트가 없어도 남습니다:

```
단계: S4 구현 (3/7 기능)          마지막 갱신: 2026-10-02 21:10
한 일: 온보딩 · 기록 화면 머지, 실기기 시험 초록 (아이폰12 · 갤럭시 S21)
다음: 알림 · 통계 화면
막힘: 없음
주인 할 일: 없음
```

「주인 할 일」이 비어 있지 않으면 **복사해서 붙여 넣을 수 있는 값**까지 적습니다
(어느 화면 → 어느 칸 → 무엇). "~를 설정해 주세요" 로 끝내지 않습니다.

### 출시 요청 (S6 끝)
출시 창구(`app-factory-ship`)의 ship 워크플로를 실행하면 GitHub 이 주인에게 승인 요청 알림을
보냅니다. 그 전에 상황판과 출시 PR 본문에 아래를 채웁니다:

- 무엇이 바뀌었나 (사용자 말로 3줄) · 스토어 「새로운 기능」 문구
- 시험 결과: 단위 n개 · 통합 n개 · 실기기 (기기 이름별 초록/빨강) · 스크린샷 링크
- 알고 내는 문제 (있으면) · 되돌리는 법
- 이번 출시로 무엇을 보려는가 (지표 하나와 판정 날짜)

### 하루 요약
매일 밤 루틴(`daily-digest` 스킬)이 모든 상황판과 지표를 읽고 한 번 알립니다. 그 사이에는
**주인이 무언가를 해야 할 때만** 알립니다(출시 승인 요청 · 막힘 · 심사 반려 · 장애).

## 6. 주인에게 묻는 것 / 묻지 않는 것

**묻는 것 (주인만 할 수 있음):** 출시 승인 · 돈이 드는 일 · 계정 단위 계약과 세금 ·
본인 인증 · 스토어 콘솔에서만 되는 첫 등록 칸 · 앱을 접는 결정 · 법적 판단이 필요한 것.

**묻지 않는 것 (Claude 가 정하고 이유를 남김):** 화면 구성 · 색 · 문구 · 기술 선택 ·
시험 방법 · 가격 초안(출시 요청에서 주인이 바꿀 수 있음) · 버그 우선순위.

**다른 세션에 말할 때** (`docs/factory/SESSIONS.md`): 정해진 기기 작업은 워크플로 실행, 즉석 일만 `mac-lab`
에 세 줄 메시지([요청] · [결과 놓을 곳] · [급함]). 다른 스레드가 알아야 할 결정 · 함정은 대화에 두지 않고
프로젝트 기억("기억해 둬") 또는 저장소에 씁니다. 주인에게 세션 사이를 전달해 달라고 하지 않습니다.

모호하면 되돌리기 쉬운 쪽을 고르고 진행합니다. 되돌리기 어려운 것(번들 ID · 앱 이름 확정 ·
서버 주소 · 데이터 형식)은 S2 기획서에 적어 두면 주인이 보고에서 봅니다.

## 7. 저장소 구조와 이름

```
apps/<이름>/            Flutter 앱 하나 (번들 ID: io.github.<주인>.<이름> — 한 번 정하면 못 바꿈)
packages/               앱들이 같이 쓰는 것 (결제 벽 · 설정 · 법적 화면 · 측정 · 디자인 토큰)
portfolio/<이름>/       조사 · 기획 · 설계 · 품질 보고 · 스토어 문안 · 지표
portfolio/ideas.md      주제 대기열과 점수
.github/workflows/      ci · device-lab · release-candidate · ship
.maestro/ 또는 apps/<이름>/.maestro/   실기기 흐름 시험
```

- 판 번호: `1.<기능 판>.<고침>` · 빌드 번호 = 저장소 커밋 수 (두 스토어가 같은 번호)
- 브랜치: `claude/<앱>-<일>` → PR → main. 출시는 main 의 태그 `<앱>-v<판>`
- 커밋 메시지: 한국어, 첫 줄에 앱 이름 — `습관: 알림이 두 번 오던 것 고침`
- 공통 코드는 `packages/` 로 올리되, **화면 모양과 핵심 기능은 앱마다 다르게** (4.3)

## 8. MyBody 에서 배운 것

| 겪은 일 | 규칙 |
|---|---|
| 시험 안에서 플랫폼 플러그인 `await` 가 영영 안 돌아와 시험이 멈춤 (예외도 timeout 도 없음) | 앱 부팅은 플러그인을 기다리지 않는다. 시험에는 가짜 플러그인을 꽂는다 |
| 릴리스 빌드에서 화면 예외 → 글자 없는 회색 네모, 콘솔에도 안 찍힘 | 화면마다 세워서 `ErrorWidget` 검사. **밀어 올린(push) 화면도** |
| 에뮬레이터에 한글 입력기가 없어 한글 검색을 못 쳐 봄 | 한글 입력 시험은 실기기에서, 또는 시험 코드에서 직접 넣기 |
| 클라우드 ↔ 노트북 세션이 문서 우편함으로 일을 주고받음 — 주인이 "15번 해줘" 를 전달해야 했음 · SendMessage 는 승인에 걸려 포기 | 기기 시험은 CI 잡(self-hosted runner)이 돈다. 즉석 일은 세션 메시지 — 받는 쪽 `crossSessionInbound: accept` 로 승인 문제 없음 |
| 서버 주소를 바꾸면 사용자 기록이 새 주소에서 안 보임 | 서버 주소는 첫 출시 전에 고정 (도메인 또는 고정 이름) |
| 판독 신뢰도 점수가 틀린 값에 더 높은 점수를 줌 | "그럴듯한 틀린 값" 이 제일 위험 — 값끼리 검산하는 규칙으로 막는다 |
| 안드로이드 7~11 이 정확하지 않은 알람을 묶어 알림이 몰려 옴 | 시각이 중요한 알림은 기기 판마다 실기기에서 확인 |
| 동의 문구와 실제 동작이 어긋남 → 심사 대비로 고쳐 씀 | 개인정보 답안(애플 · 구글)은 코드에서 뽑은 데이터 흐름표와 대조 |
| 판 번호가 두 스토어에서 갈라짐 | 빌드 번호 = 커밋 수 한 갈래 |
