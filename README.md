# Mybody

인바디(InBody) 결과지 한 장에서 현재 몸 상태를 읽고, 목표 체중·골격근량·체지방량을 입력하면
**언제 달성 가능한지**와 그때까지의 **운동·식단 계획**을 만들어 주는 개인용 앱.

> 현재 단계: **배포 직전**. 자가호스팅 서버(계정 · 친구 · 공유)와 결과지 판독이 들어가 있습니다.
> `node tools/preflight.js` 가 초록이면 올릴 수 있습니다. 올리는 법은 `docs/DEPLOY.md`.
>
> **다음 앱들을 위한 공장 설계**(이 앱을 만들며 겪은 것을 데이터로 삼음)는 [`factory/`](factory/README.md).
>
> **데이터가 어디에 있는지** — 측정 기록 · 프로필 · 목표 · 계획 · 식단은 이 기기에만 있습니다.
> 로그인하면 친구에게 보일 **주간 요약**(최근 체중 · 골격근 · 체지방과 그 변화량)이 서버로
> 올라갑니다. 자동 판독을 직접 켜면 그때만 **결과지 사진**이 서버를 거쳐 외부 판독 서비스로
> 갑니다. 기기를 바꾸면 기록은 따라오지 않습니다 — 백업은 설정의 내보내기입니다.

```bash
cd prototype && python3 -m http.server 8000
```

## 피드백 하는 법

화면의 모든 요소에 작은 고유번호 배지가 붙어 있습니다.

| 조작 | 결과 |
|---|---|
| 배지 클릭 | `P06-B21 · 중 선택` 형태로 클립보드에 복사 |
| **Shift** + 배지 클릭 | 그 요소에 메모 달기 (로컬 저장) |
| **Alt** + 배지 클릭 | 딥링크(`#P06-B21`) 복사 |
| `i` 키 | 배지 전체 켜기/끄기 |
| `f` 키 | 피드백 모드 — 아무 요소나 클릭하면 메모창 |
| `?` 키 | 단축키 도움말 |

메모를 다 달았으면 우하단 **내보내기** 버튼 → 마크다운이 클립보드에 복사됩니다. 그대로 붙여넣어 주세요.

### 번호 읽는 법

```
P06-B21
│   │└─ 21번째 버튼
│   └── B = 버튼 (F 입력 · C 카드 · T 탭 · L 리스트 · G 차트 · S 상태 · N 내비)
└────── P06 = 실현 강도 선택 화면 (M = 팝업, A = 토스트)
```

번호는 **화면 안에서만** 매겨지고, 한 번 배정되면 바뀌지 않습니다.
화면이 추가돼도 기존 번호는 그대로입니다.

## 설계의 핵심 결정

### 0. 몸 만들기 모드 7종 — 변화량을 넣으면 자동으로 골라집니다

업계에서 실제로 쓰는 국면을 조사해 정리했습니다. 이름을 붙인 게 아니라 **서로 다른 계획**입니다.

| 모드 | 다른 말로 | 방향 | 성격 |
|---|---|---|---|
| **감량모드** | 다이어트 · 감량기 | 적자 | 체중과 체지방을 함께 줄인다. 근육은 지키는 게 목표 |
| **커팅모드** | 컷팅 · 시즌 · 바디프로필 준비 | 적자 | 이미 있는 근육을 드러낸다. 근손실 최소화가 조건 |
| **리컴프** | 상승다이어트 · 동시개선 | 거의 유지 | 근육은 올리고 지방은 내린다. 느리지만 조건이 맞으면 분할보다 빠름 |
| **근성장모드** | 린매스업 · 벌크업 · 증량기 | 잉여 | 근육을 늘린다. a를 올리면 벌크업, 내리면 린매스업 |
| **유지모드** | 유지어트 · 유지기 | 유지 | 지금 몸을 지킨다. 처방된 국면이지 아무것도 안 하는 게 아님 |
| **회복모드** | 리버스 다이어팅 · 회복식 | 완만한 잉여 | 감량을 끝내고 정상 섭취로 돌아가는 구간 |
| **단기커팅** | 미니컷 | 깊은 적자 | 증량 중에 끼우는 3~5주. 단독으로 고르는 모드가 아님 |

**감량과 커팅은 합치지 않았습니다.** 같은 방향이지만 커팅이 더 보수적입니다
(공격성 상한 0.75 vs 0.90, 단백질 하한 2.4 vs 2.2 g/kg 제지방).
체지방률 게이트(남 18%)로 갈리고, 게이트 위에서 커팅을 누르면 왜 안 열리는지 화면이 설명합니다.

목표 변화량을 넣으면 **23개 순서 규칙**을 위에서부터 평가해 모드가 자동으로 정해지고,
왜 그 모드인지와 다른 모드가 왜 안 열리는지를 함께 보여줍니다.
직접 고를 수도 있고, 그때는 경고가 그대로 남습니다.

규칙보다 먼저 **10개 거부 조건**이 걸립니다 — 저체중, 필수지방 미만, 방향이 반대인 목표,
주당 1.5% 초과, 19세 미만 감량, 세 숫자 불일치, 4주 미만 기간 등.

### 1. 실현 강도 상/중/하 = 난이도가 아니라 **기간**

엔진이 먼저 생리적으로 가능한 **최단 기간 `T_min`** 을 찾고, 거기서 세 갈래로 나눕니다.

| 강도 | 기간 | 성격 |
|---|---|---|
| **상** | `T_min` | 가장 빠름. 식단 제약 최대, 근손실 위험 가장 큼 |
| **중** | `T_min × 1.4` | 균형점 |
| **하** | `T_min × 2.0` | 생활 유지. 중도 포기 확률 최저 |

각 카드에 **실제 달력 날짜**가 박히고, 플랜 화면에는 D-day와 주차별 궤적이 나옵니다.

### 2. 강도를 올리면 오히려 느려질 수 있다 — 숨기지 않는다

적자가 TDEE의 15%를 넘어가면 근육 증가율이 거의 0으로 떨어집니다.
그래서 **근육 목표가 병목일 때는 공격적인 계획이 전체 기간을 늘립니다.**
엔진은 공격성 `a ∈ [0,1]` 을 51개 지점에서 스캔해 이 역설을 찾아내고, 발견되면 경고로 띄웁니다.

또 리컴프 목표에서는 두 전략을 모두 시뮬레이션해 더 빠른 쪽을 고릅니다.

- **동시 진행** — 지방을 빼면서 근육도 늘린다 (적자가 작을 때만 성립)
- **분할** — 감량 → 유지 2주 → 증량 → 미니컷

### 3. 주차별 시뮬레이션

나눗셈 한 번이 아니라 주 단위로 상태를 전진시킵니다. 체중이 줄면 TDEE가 줄고,
체지방이 줄면 안전하게 동원 가능한 에너지 상한(`31 × 체지방량` kcal/day)도 함께 줄기 때문입니다.
이 덕분에 궤적 차트와 4주 단위 마일스톤이 그냥 직선이 아니라 실제 곡선으로 나옵니다.

### 4. 측정 노이즈보다 작은 변화는 "변화"라고 부르지 않습니다

인바디가 실제로 재는 것은 임피던스에서 추정한 체수분 하나뿐이고 나머지는 전부 산수입니다.
체수분이 1L 틀리면 제지방이 1.37kg, 체지방이 1.37kg, 체지방률이 1.58%p 틀립니다.

그래서 노이즈 바닥을 **체중 ±1.0kg · 골격근 ±0.6kg · 체지방 ±1.0kg** 으로 잡았습니다.
이보다 작은 목표를 넣으면 "기계가 구분하지 못하는 크기"라고 말하고 유지모드로 보냅니다.
측정 간격이 4주 미만인 추세는 판정에 아예 쓰지 않습니다.

### 5. 근육이 빠지는 경로를 실제로 넣었습니다

처음 버전의 엔진은 골격근이 줄어들 수 없는 구조였습니다. 그래서 어떤 무리한 계획에도
"근육은 유지됩니다"라고 답했는데, 그건 예측이 아니라 모델의 산물이었습니다.
지금은 적자가 TDEE의 20%를 넘거나, 단백질이 2.0 g/kg 제지방 아래거나,
체지방률이 남 10% / 여 18% 아래면 주당 제지방이 0.05~0.15% 빠집니다.
계획 기간 동안 0.3kg 넘게 빠질 것으로 계산되면 강도 카드에 경고가 붙습니다.

### 6. 판독 검수 화면은 선택이 아니라 필수

판독은 사람이 하든 기계가 하든 틀립니다. 그런데 틀린 값은 깨져 보이지 않고 *그럴듯해* 보입니다 —
골격근량이 28.1 대신 25.1 로 들어가도 화면은 멀쩡하고, 사용자는 한 번도 본 적 없는 숫자를 그대로
믿게 됩니다. 그 상태로 4주를 보내면 "앱이 틀렸다" 가 아니라 **"내 몸이 이상하다"** 고 결론짓습니다.

그래서 결과지 안에서 검산합니다. 인바디 결과지는 내부적으로 수식이 맞아떨어지는 문서입니다 —
`제지방 = 체중 − 체지방`, `체수분 + 단백질 + 무기질 + 체지방 = 체중`, `기초대사량 ≈ 370 + 21.6 × 제지방`.
한 칸을 잘못 읽으면 다른 칸과 어긋납니다. 규칙 8개가 돌고, 지난 측정이 있으면 골격근 비율까지 봅니다.

**OCR 신뢰도 점수는 안 씁니다.** 시험 삼아 떠 보니 맞은 값 24.8 에 14점, 틀린 값 19.3 에 39점을
줬습니다. 글자를 얼마나 선명하게 봤는지는 그 숫자가 맞는지와 거의 상관이 없습니다. 화면의 점은
검산 상태입니다 — 검산됨 / 미검산 / 모순.

## 화면 구성

| ID | 화면 | 역할 |
|---|---|---|
| `P00` | 앱 셸 | 앱바 · 하단 탭바 |
| `P01` | 온보딩 · 프로필 | 성별/나이/키/활동수준/운동경력/제약 |
| `P02` | 홈 대시보드 | 최신 인바디 · 목표 진행 · 오늘 할 일 |
| `P03` | 인바디 넣기 | 사진 + 숫자 세 칸 직접 입력 (+ 켜면 서버 자동 판독) |
| `P04` | 판독 검수 | 값 확인·수정 (결과지 안에서 검산 — 검산됨/미검산/모순) |
| `P05` | 목표 설정 | 목표 3종 + 모드 자동선택 + 실시간 실현가능성 |
| `P06` | 실현 강도 선택 | 상/중/하 = 기간, 각각 달성 예정일 |
| `P07` | 플랜 | 요약 · 운동 · 식단 탭 + 궤적 + 마일스톤 |
| `P08` | 주간 체크인 | 실측 입력 → 예상 대비 비교 → 재조정 |
| `P09` | 진행 추적 | 지표별 추이 + 예측 도달일 재계산 |
| `P10` | 히스토리 | 측정 기록 목록 |
| `P11` | 스캔 상세 | 개별 측정 전체 필드 |
| `P12` | 설정 | 프로필 · 표시 · 결과지 사진 · 데이터 (+ 개발 빌드에서만 도구) |
| `P13` | ID 인덱스 | 고유번호 검색 + 피드백 목록 |

팝업 `M01`~`M25`, 토스트 `A01`~ 은 화면에 종속되지 않는 전역 번호입니다.

## 검증

```bash
NODE_PATH=/opt/node22/lib/node_modules node tools/smoke.js
```

모든 화면을 실제 브라우저로 돌면서 JS 오류, 고유번호 규칙 위반(형식·중복·타화면 번호·라벨 누락),
빈 화면을 잡습니다. 판독 경로도 클릭해서, 일부러 틀리게 넣은 값을 검수 화면이 잡는지 확인합니다.

의존성 없음. 번들러 없음. 앱은 오프라인으로 돕니다 — 계산도 저장도 전부 기기 안에서 일어납니다.
서버는 친구 기능과(켰다면) 자동 판독에만 씁니다.

검사 전체는 한 줄입니다:

```bash
node tools/preflight.js
```

빨간 줄이 없으면 배포해도 됩니다. `FAST=1` 을 붙이면 브라우저를 띄우는 검사를 건너뜁니다.

## 아직 안 된 것

- **기록 동기화** — 측정 기록 · 프로필 · 목표 · 계획 · 식단은 서버로 안 올라갑니다.
  기기를 바꾸면 안 따라옵니다. 지금 백업 수단은 설정 → 내보내기(JSON) 하나입니다.
- **비밀번호 찾기** — 없습니다. 이 서버는 메일을 보내지 않습니다. 잊으면 서버 주인이
  DB 에서 계정을 지우고 다시 만드는 수밖에 없습니다.
- **알림** — 체크인 리마인더 UI만 있고 실제 알림은 가지 않습니다.

  쪽이 지금은 더 빠르고 정확합니다.
