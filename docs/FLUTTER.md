# 앱으로 옮기기 — 지금 어디까지 왔나

쓰던 웹 앱(`prototype/`)을 설치하는 앱(`app/`, Flutter)으로 옮기는 중입니다.
**두 앱은 같은 서버를 봅니다.** 그래서 옮기는 동안 친구들은 지금 것을
계속 쓰면 됩니다.

## 구조

```
packages/mybody_core/   화면 밖의 로직 전부 (순수 Dart — Flutter 를 안 깔아도 돌아갑니다)
  crosscheck.dart         결과지 안 숫자끼리 맞는지 검산
  engine.dart             계획 엔진 — 주차별 시뮬레이션 · 상/중/하 · 매크로 · 운동 · 식단
  modes.dart              몸만들기 모드 선택 (거부 10 · 규칙 23)
  store.dart              상태 저장소 (백업 파일이 웹 앱과 **같은 판**입니다)
  schedule.dart           주간 일정과 스트릭
  suggest.dart            "단백질 40g 남았는데 뭘 먹지"
  fooddb.dart             식품 90여 개
  data.dart · modes_data.dart · fooddb_data.dart   ← 전부 **찍어낸 것**

app/                    화면 (Flutter)
  lib/src/ui/             조각들 — 카드 · 숫자 · 차트 · 기호
  lib/src/screens/        화면
```

## 검증

### 1. 차이 검사 — 옮긴 로직이 원본과 **같은 답을 내는가**

```
node tools/difftest.js
```

같은 입력을 자바스크립트와 Dart 양쪽에 넣고 **글자 단위로** 비교합니다.
모듈 43개, 씨앗을 고정한 무작위 입력 수천 개씩. 하나라도 갈리면 그 입력을
그대로 보여 줍니다.

이렇게 하는 이유: 검산과 엔진은 **눈으로 못 봅니다.** 틀려도 그럴듯한
숫자가 나오고, 사용자는 그 숫자를 믿습니다. "옮겼습니다" 라는 말로는
아무것도 보증되지 않습니다.

실제로 이 검사가 잡은 것들:
- 나이를 안 적은 사람의 근성장이 10% 깎이고 있었습니다
  (`undefined < 18` 은 거짓, `null < 18` 은 참)
- 숙련자·상급자가 리컴프 모드로 들어오고 있었습니다 (규칙 하나를 잘못 읽음)
- 원본의 정렬 하나가 **명세에 없는 동작**에 기대고 있었습니다

### 2. 화면이 서는가

```
cd app && flutter test
```

릴리스 빌드에서 화면을 그리다 예외가 나면 Flutter 는 **아무 글자도 없는
회색 네모**를 그립니다. 콘솔에도 안 찍힙니다. 그래서 화면마다 한 번씩
세워 보고 `ErrorWidget` 이 나오는지 봅니다.

**밀어 올린 화면(push)도 봅니다.** 화면을 직접 세우는 것과 앱처럼 밀어
올리는 것은 다른 일입니다 — 그 차이를 안 봐서, 시험 열아홉 개가 통과하는
동안 검수 화면이 릴리스에서 통째로 회색이었습니다.

**시험 안에는 플랫폼 플러그인이 없습니다.** 폴더 위치를 묻는 것 같은
플러그인 호출은 시험에서 **영영 안 돌아옵니다** — 예외도 안 나고, 시험은
시계를 멈춰 놓고 돌아서 `timeout` 도 안 울립니다. 실제로 앱이 켜질 때
사진 보관소를 `await` 하다가 첫 번째 화면 시험이 그 자리에서 멈췄습니다.
그래서 앱은 그런 것을 **기다리지 않고** 뜹니다 (`AppState.boot`) — 폰에서는
첫 화면이 그려지기 전에 열리고, 시험에서는 사진 없이 돕니다.

### 3. 글꼴 — 앱이 그리는 글자가 앱 안에 다 있는가

글꼴은 **Pretendard** 입니다 (한글 11,172자 전부). 없는 기호 몇 개는 크기
단위가 같은 글꼴에서 떼어다 붙입니다 — 단위가 다른 데서 가져오면 그 글자만
커집니다.

```
node tools/test-fontcover.js      # 확인
node tools/fix-fonts.js           # 빠진 글자 채우기
```

Flutter 는 글꼴에 없는 글자를 `fonts.gstatic.com` 에서 받아 오려 합니다.
망이 막힌 곳에서는 네모가 되고, 안 막힌 곳에서는 몸 관리 앱을 켤 때마다
구글에 신호가 갑니다.

처음 쟀을 때 화면 한 번 도는 동안 **1,900건**이 나갔습니다.

마지막 한 건은 글자가 빠져서가 아니었습니다. CanvasKit 은 `Roboto` 라는
이름의 글꼴이 앱에 없으면 **쓰든 안 쓰든** 받아 옵니다. 그래서 그 이름표를
단 작은 조각(Pretendard 의 라틴 부분)을 넣었습니다.

**지금은 0건입니다.** 망을 통째로 막아 놓고 화면을 한 바퀴 돌아서 쟀습니다
— 밖으로 나가려 한 요청이 하나도 없고, 글자도 네모가 안 됩니다.

### 4. 눈으로 보기

```
node tools/build-flutter-web.js
STATIC=app/build/web node tools/serve.js
```

**웹 앱과 다른 것 하나 — 로그인이 먼저입니다.** 결과지 사진 판독은 서버가
사람마다 횟수를 세는 일이라 계정이 있어야 됩니다. 웹 앱은 계정 없이도
들어가게 두고 판독할 때 막았는데, 그러면 첫 판독이 실패로 끝나는 게
첫인상이 됩니다. 앱은 로그인/가입을 먼저 세우고, 그 다음 온보딩입니다.

**웹 앱보다 더 가는 것 — 기록이 내 계정에 저장됩니다.** 예전엔 "몸 숫자는 이
기기에만" 이었고 내보내기가 유일한 백업이었습니다. 주인이 바꿨습니다: 상태
전체를 한 레코드로 내 계정에 올리고(`cloud.dart`, 저장할 때 3초 모아서), 켤
때와 로그인할 때 받아 봅니다. 막 깐 기기는 무조건 받고, 아니면 **마지막에
바꾼 쪽**이 이깁니다. 웹 앱도 저장할 때 같은 레코드를 올리니, 웹에서 쓰던
사람이 앱을 깔고 로그인하면 그대로 따라옵니다. 사진은 안 갑니다. 동의문
판을 2026-09-22 로 올렸는데 **문구는 그대로**("주간 요약만 · 52주까지만")였습니다.
0.2.5 에서 문구를 실제대로 고쳤고(판은 옛 서버·심사 중 앱 때문에 그대로), 0.2.6 에서
서버가 옛 판도 받게 한 뒤 판을 2026-09-23 으로 올렸습니다. 문장은 가입 카드와 다시
묻는 화면이 같이 쓰도록 `HealthConsentPoints` 한 곳에 있습니다. 옛 판으로 가입한
사람은 켤 때 `ConsentGate` 가 한 번 다시 묻고(`POST /api/me/consent`), 거부하면
로그아웃하고 「로그인 없이 쓰기」로 이어 갑니다. 서버가 안 닿으면 막지 않습니다.

**주간 체크인은 흔들림에 반응하지 않습니다.** 예전 판정은 이번 주 체중 하나를
계획선에 대 보고 0.15kg 만 달라도 "빠릅니다 · 150kcal 늘리기" 를 냈고(계획 다음 날
집 체중계와 인바디 차이 0.5kg 로), 저장한 체크인은 어디에도 안 쓰였습니다. 지금은
코어 `checkinReview`(웹 · 앱 같은 함수, difftest 로 확인)가:
체크인마다 그날 자리의 계획선과의 차이를 구해 **직선 추세**를 맞추고(체중계 차이는
지워짐), 계획 주마다 마지막 값 하나 · 이웃한 두 값이 5일 안이면 앞의 값을 버리며(앱도 같은
주에 다시 저장하면 그 주 값을 바꿈), 3주(21일) 이상 · 4번 이상부터 판정합니다.
추세가 1kg 넘게 · 흔들림에 비해 확실하게(기울기/표준오차 ≥ 2.5) 벗어나는 일이
**두 번 연속** 체크인에서 보일 때만 조정(무거워지면 −150, 가벼워지면 +150, 감량 중
무거워지면 유산소 +40분)을 제안합니다. 방향은 그 시점 계획의 단계(phase)이고, **추세도
지금 단계 안에서만** 맞춥니다(감량 → 유지 → 증량이면 단계가 바뀔 때 조정 때처럼 다시 모음 —
감량 때 정체해 쌓인 차이가 증량 추세로 읽혀 "빨리 는다 · 줄이기" 가 나왔습니다). 유지 단계는
체중 자체도 같은 쪽으로 움직였을 때만이고, 체중이 실제로 1kg 안에서 그대로일 때만
"지키고 있습니다". 모의실험(계획대로 가는 사람, 흔들림 σ 0.5kg, 12주)에서 가짜 조정은
약 5%(예전 규칙 30~60%), 주 0.5kg 감량 계획의 완전 정체는 체크인 5~6번이면 잡힙니다.
느린 계획(주 0.15~0.25kg)의 정체는 차이가 천천히 쌓여 7~9주 걸립니다(최근 몇 주만 보게
하면 가짜 조정이 늘고 절반을 놓쳐서, 단계 안의 체크인 전부를 봅니다).
「저장하고 제안 적용」은 `applyCheckinAdvice` 로 plan.macros 를 바꾸고(식단 탭 목표에 바로
반영, 하한 밑으로 안 내림, 바뀌는 숫자를 먼저 보여 줌), 조정 뒤에는 그 체크인부터 다시 봅니다.
체크인은 이 화면 그래프 · 「지난 체크인」(지우기 가능) · 홈 「이번 주 체크인 완료」 · 추이 탭
점선에 나옵니다. 넣는 값은 20~300kg · 가장 최근 기록과 너무 다르면 막습니다(862 오타).
이번 주에 잘못 저장한 값은 다시 넣어 바꿀 수 있습니다(바뀔 값과는 견주지 않음).

**「이 기기에서 전부 지우기」는 로그아웃까지 합니다.** 로그인이 남으면 다음에
켤 때 동기화가 계정 사본을 받아 와 지운 기록이 되살아나고, 그 전에 온보딩을
다시 하면 빈 기록이 계정 사본을 덮어씁니다. 못 보낸 큐(기록 사본이 들어 있을 수
있음)도 비웁니다 — 이 기기를 넘겨받은 사람의 계정으로 올라가지 않게.

**웹 앱보다 더 가는 것 — 친구 상세.** 원본은 친구 화면에 내가 뭘 공유하는지가
먼저였고 친구에 대한 건 숫자 네 개였습니다. 앱은 친구에 대한 것이 먼저입니다:
운동·식단 스트릭, 오늘 식단(칼로리·탄단지, 목표 대비), 이번 주 운동(요일별).
그래서 서버 스냅샷에 `streaks` · `today` · `week` 가 들어가고, 공유 항목에
`diet`(기본 켜짐) 가 생겼습니다. 요일별 일정은 원본이 일부러 안 보내던 것인데
주인이 결정을 바꿨습니다 — 같이 운동하자고 맺은 사이에서는 "화요일에 헬스
갔네" 가 바로 그 확인이라고. 한 번 눌러 끌 수 있는 건 그대로입니다.

아이콘은 Lucide(선 아이콘)입니다. 별표 둘만 Material 그대로 — 채운 별과 빈
별의 구분이 필요해서.

## 아직 안 옮긴 것

- **친구 소식 폰 알림** — 옮길 수가 없습니다. 서버가 쓰는 것은 **웹 푸시
  (VAPID)** 라 브라우저 전용입니다. 설치하는 앱에서 서버가 보내는 알림을
  받으려면 FCM 이 필요하고, 그건 주인이 Firebase 프로젝트를 만들어
  `google-services.json` 을 넣어야 시작됩니다.

  **간식 단백질 알림은 됩니다** — 서버가 아니라 폰이 직접 예약합니다
  (`nudge.dart`). 앱을 켤 때와 먹은 것을 적을 때 남은 단백질을 계산해, 다음
  간식 시각(15:30 · 20:30)에 "단백질 42g 남았어요. 간식으로 …" 를 걸어
  둡니다. 15g 안 남았으면 안 웁니다. 설정에서 끌 수 있습니다.

  친구 소식 자체는 옮겼습니다 — 앱을 열면 **친구 탭 → 소식**에 쌓여 있습니다.
  알림이 울리지 않을 뿐입니다.
