| F5 | 가장자리 잘림 | 측정일시 프레임 밖 | 네 귀퉁이 오버레이 프레임 |
| F6 | 소수점 소실 | `63.4` → `634` | T1 범위 검증에서 반드시 잡힘 |
| F7 | **축 눈금 미끼** ★최위험★ | `골격근량 28.1 kg \| 55 70 85 100 115` | §4.2 황금 규칙(소수점 유무 판별) |
| F8 | 표준범위 괄호 | `28.1 kg (24.8~30.3)` | 괄호 내부 제외 |
| F9 | 2단 편집 읽기 순서 붕괴 | 좌/우 열이 교대로 섞임 | bbox 열 분리 / 레이아웃 이해 |
| F10 | 체지방`량` vs 체지방`률` | kg ↔ % 혼동 | 단위 + C2 교차검증에서 즉시 발각 |
| F12 | 비인바디/구형 양식 | 라벨 자체가 다름 | 수동 입력으로 우아하게 강등 |
| F13 | 앱 스크린샷 / 거울상 | 레이아웃 전혀 다름 | 별도 프로파일 |
| F14 | 측정일시 누락 | 시계열 붕괴 | EXIF prior → 없으면 사용자 필수 입력 |

**기기별 차이**: InBody 270(감열지 흔함, 항목 적음) / 370 / 570 / 770(글자 작음) / Dial·앱 캡처는 **항목 구성이 다르다.** 파서는 *"이 모델이면 이 항목이 반드시 있다"*고 가정하지 않고 **"있으면 읽고 없으면 null"**로 동작한다. `P04`의 필드 리스트는 `value === null && confidence === 0`인 비필수 항목을 기본 접힘 상태로 둔다(오너가 자기 기계에 없는 항목을 찾아 헤매지 않게).

### 4.4 검증 규칙 (순수 함수, 프로토타입에서 진짜로 구현)

**T0 구조**: 필수 키 존재 · 숫자 파싱 가능 · `NaN`/`Infinity` 아님 · 단위 기대값 일치 · `measured_at` 파싱 가능 & 미래 아님 & 10년 이내 · `schema_version` 호환.

**T1 범위** (hard = 값 폐기·필수 수정 / soft = 경고 후 확인)

| 필드 | hard | soft |
|---|---|---|
| 체중 kg | 25–250 | 40–120 |
| 신장 cm | 120–220 | 145–195 |
| SMM kg | 8–60 | 18–42 |
| BFM kg | 1–120 | 5–45 |
| PBF % | 2–65 | 남 8–30 / 여 18–38 (성별 조건부) |
| BMI | 10–55 | 16–35 |
| FFM kg | 20–130 | 35–70 |
| TBW L | 15–90 | 25–50 |
| 단백질 kg | 3–25 | 7–14 |
| 무기질 kg | 1–10 | 2.5–5 |
| BMR kcal | 700–3500 | 1100–2000 |
| VFL | 1–30 (정수) | 1–15 |

> **[결정]** PBF 상식 범위(`C10`)는 T1 soft의 **성별 조건부 범위와 중복**이므로 삭제. PBF 경계는 hard/soft **두 벌만** 존재한다.

**T2 내부 일관성** — OCR 오류를 잡는 최고의 무기

| ID | 규칙 | 허용오차 | 잡는 오류 |
|---|---|---|---|
| `C1` | `FFM = 체중 − BFM` | ±0.3 kg | 셋 중 하나의 오독 |
| `C2` | `PBF = BFM / 체중 × 100` | ±0.5 %p | **소수점 오류, 량/률 혼동** |
| `C3` | `BMI = 체중 / 신장m²` | ±0.3 | 자릿수 오류 |
| `C4` | `TBW + 단백질 + 무기질 + BFM = 체중` | ±0.5 kg | 체성분 분석 열 전체 검산 |
| `C5` | `TBW ≈ 0.72 × FFM` | ±10% | TBW 오독 |
| `C6` | `SMM < FFM` **그리고** `SMM/FFM ∈ [0.42, 0.62]` | – | **`33.2`를 `53.2`로 읽는 유형 (핵심)** |
| `C7` | `Σ(부위별 근육 5부위) ≈ FFM × 0.90` | **±8%** | 부위별 표 오독 |
| `C8` | 좌/우 팔·다리 차이 ≤ 25% | – | 한쪽 자릿수 오류 |
| `C11` | `체중조절 = 적정체중 − 체중` (부호 포함) | ±0.5 kg | 조절 박스 검산 |
| `C12` | `ICW + ECW = TBW` | ±0.3 L | 수분 분해 검산 |
| `C13` | PBF 낮은데 VFL ≥ 15 | 느슨 | info |

> **[결정]** `C7`의 계수를 **0.80 → 0.90, 허용오차 ±15% → ±8%**로 고친다. 5개 세그먼트는 머리를 제외한 전신을 덮으므로 실제 합은 FFM의 0.88–0.92다. 0.80 중심은 허용 예산 전부를 자기 편향 보정에 쓰고 진짜 오독을 못 잡았다.
> **[결정]** 인쇄 BMR 대조(`C9`)는 **삭제**한다. ±15% 허용은 본 앱이 "4주를 망친다"고 규정한 ±200 kcal 오차를 그대로 통과시키므로 항상 통과하는 잡음이다. 인쇄 BMR은 검증 대상이 아니라 `W-BMR-01` 표시 대상일 뿐이며, 계산에는 애초에 쓰지 않는다(§3.2).

**T3 스캔 간 변화량** (이전 확정 스캔이 있을 때만)

| 필드 | warn | error | 근거 |
|---|---|---|---|
| 체중 | \|Δ\| > 3.0 kg/주 | > 6.0 kg/주 | 하루 ±1.5kg 수분 변동과 정합 |
| SMM | \|Δ\| > 1.5 kg/주 | > 3.0 kg/주 | BIA 수분 기반 추정의 노이즈 |
| BFM | \|Δ\| > 2.5 kg/주 | > 5.0 kg/주 | 체중·PBF 임계에서 유도 |
| PBF | 체중·BFM 임계에서 **유도** | 유도 | 독립 임계 금지 |
| 신장 | \|Δ\| > 1 cm | > 3 cm | **다른 사람 결과지 신호** |
| 성별 | 변경 시 | – | 다른 사람 결과지 신호 |

> **[결정]** 원안의 SMM 0.5 kg/주 warn은 **모든 정상 측정에서 발화**한다(동일인 재측정 변동이 0.5–1.0 kg). 임계를 3배로 올리고, PBF는 독립 임계 대신 체중·BFM에서 유도해 **하나의 원인에 하나의 경고**만 뜨게 한다. 가짜 경보는 `M08`을 반사적으로 닫는 습관을 만들고, 그러면 진짜 이상치를 놓친다.
> **[결정]** `device_model` 또는 `sheet_type`이 직전 스캔과 다르면 **T3 경고를 전부 info로 강등**하고 "기기가 바뀌어 비교가 어렵습니다 — 가능하면 같은 기계를 쓰세요"를 표시한다. `measure_condition`이 다를 때도 동일.

부가: `measured_at`이 최신보다 과거 → 오류 아님, `backfill`로 시계열 삽입. `image_hash` 또는 (일시+체중) 동일 → `M09` 중복 감지.

**T4 자릿수 오류 자동 제안** — **후보 순위가 핵심**
```
1순위 (derived) : 통과하는 정합성 항등식에서 직접 유도한 값
                  예) PBF = BFM/체중×100 = 27.1  ← 이것이 정답
2순위 (heuristic): 소수점 이동(v/10, v×10), 앞 두 자리 자리바꿈, 문자 혼동(8↔3,5↔6,1↔7,0↔8,4↔9)
채택 조건: 변형 후 T1 hard·soft와 T2 전부를 통과하는 후보만 제시. 통과 후보가 없으면 제안하지 않는다.
메시지에는 반드시 이유를 붙인다: "체지방량 17.2kg ÷ 체중 63.4kg = 27.1% 입니다"
```
> **[결정]** 원안은 `2.21` → `22.1`(소수점 이동)을 제안했으나, `22.1`은 C2를 5.0%p 차이로 실패한다 — 사용자가 제안을 눌러도 250ms 뒤 재검증에서 다시 빨강이 된다. **파생 후보가 휴리스틱 후보를 이긴다**를 규칙으로 못박고, 문서·샘플의 모든 `22.1`을 `27.1`로 교체했다.

**T5 파생 및 조정**
- `{체중, BFM, PBF, FFM}` 중 **정확히 하나만** 비어 있고 나머지가 일관되면 계산해 채운다 → `source: "derived"`, `confidence = min(입력들) × 0.95`.
- 두 값이 충돌하면(인쇄 PBF vs 계산 PBF) **둘 다 보여주고 사람이 고른다.** 자동 채택 금지.
- `height_cm`: **프로필 값이 기본 승리**. 결과지 값과 1cm 이상 다르면 `P04-C04`에 "결과지에는 {a}cm로 인쇄되어 있습니다. 어느 쪽을 쓸까요?" 선택지를 띄운다. BMI·BMR이 전부 여기에 달려 있으므로 침묵하지 않는다.
- `measured_at` 없으면 EXIF → `source:"derived"`, confidence 0.7, **검토 화면에서 사용자 확인 필수**.

**T6 상태 판정**
```
effective_confidence[f] = raw_confidence[f] × Π(관련 이슈 패널티)   // error 0.3, warn 0.7
                          ※ 반환값일 뿐, 저장된 Field.confidence는 불변 (§1.3)
status = "needs_review"  if  error 이슈 존재
                          OR 필수 5필드 중 effective_confidence < 0.90 인 것 존재
                          OR warn 이슈 존재
       = "ok"            otherwise
```
> **[결정]** `rejected` 상태를 **삭제**한다. 수동 입력 경로가 항상 있으므로 복구 불가능한 입력은 없다. 판독이 완전히 실패하면 `M04`가 받고, 거기서 `P04-S01`(빈 폼)로 내려온다. "화면 없는 상태"를 만들지 않는다.
> **[결정]** 신뢰도 경계를 **0.90 하나로 통일**한다(원안은 게이트 0.85, 신호등 0.90/0.60이 따로 놀아 "🟢인데 저장 버튼이 비활성"인 설명 불가 상태를 만들었다). 초록 ≥0.90 / 노랑 0.60–0.90 / 빨강 <0.60, 게이트도 0.90.
> `status === "ok"`여도 **검토 화면은 건너뛰지 않는다.** "ok"는 *올그린 + 버튼 한 번*을 의미할 뿐이다.

### 4.5 `P04` 검토 화면 — 왜 필수인가, 그리고 어떻게 생겼는가

**필수인 이유**
1. OCR 오류는 깨진 값이 아니라 **그럴듯한 값**으로 나타난다. 28.1 대신 25.1이 들어가도 화면은 멀쩡하다.
2. 이 숫자가 몇 주짜리 계획을 결정한다. BFM이 2kg 틀리면 일일 적자가 ~200 kcal 어긋나고, 사용자는 "앱이 틀렸다"가 아니라 **"내 몸이 이상하다"**고 결론짓는다.
3. 올그린이면 버튼 한 번, 2초. **필수화 비용이 사실상 0**인데 "자기 숫자를 한 번은 본다"는 보장을 얻는다.
4. `edited` / `original_value` 누적이 **추출기 품질을 계측하는 유일한 수단**이다. 처음부터 자동 승인하면 이 데이터가 영원히 생기지 않는다.

**신호등 & 차단 규칙**

| 색 | 조건 | 표시 |
|---|---|---|
| 🟢 | `effective_confidence ≥ 0.90` **AND** 관련 검사 전부 통과 | 한 줄 압축, 탭하면 수정 |
| 🟡 | `0.60 ≤ ec < 0.90` **OR** warn 이슈 | 펼침 + `raw_text` 노출 + `[확인]` 체크 |
| 🔴 | `ec < 0.60` **OR** `value === null` **OR** error 이슈 | 강조 입력, 제안값 있으면 프리필 |

> **차단 규칙(한 번만, 범위 명시)**: **`P04-F01`(측정일시)·`F02`(체중)·`F03`(SMM)·`F04`(BFM)·`F05`(신장) 중 하나라도 빨강이면 `P04-B10`을 비활성화한다.** 그 외 필드의 빨강은 차단하지 않는다 — "이 항목은 비워둘게요"로 넘어갈 수 있어야 한다.

**수정 수단 (전부 제공)**
1. 큰 숫자 입력(`inputmode="decimal"`, 소수점 배치된 상태, 탭하면 전체 선택)
2. **제안값 칩** (`P04-B04`) — 파생 제안 우선, 이유 병기
3. **계산값으로 맞추기** (`P04-B05`) — 정합성 배너에서 일괄 적용
4. ±0.1 스테퍼
5. **원문 보기** — `raw_text`를 고정폭으로. "아 이래서 저렇게 읽었구나"가 보이면 신뢰가 생긴다
6. **사진 확대 연동** — §4.6의 2모드
7. `P04-B13` 직접 입력 전환 / `P04-B12` 사진 다시 올리기

**실시간 재검증**: 값 수정 시 250ms 디바운스로 `validate()` 재실행. 체중을 고치면 C2·C3가 눈앞에서 초록으로 바뀐다. 이 순간의 피드백이 *"이 앱이 내 숫자를 진짜 검산하고 있다"*는 인상을 만든다. 수정된 필드는 `source:"manual", confidence:1.0, edited:true, original_value:<원래값>`.

**확정 직후 델타 확인**: `지난 측정(8/15) 대비 · 체중 −1.7kg · 골격근량 +0.5kg · 체지방률 −2.1%p`
T3 warn/error가 남아 있으면 `M08` 질문형 모달: `[맞아요, 저장]` `[수정할게요]` `[이건 다른 날 측정이에요]` — 마지막 선택지가 중요하다.

**저장 정책**: `Extraction`(불변) + `InBodyScan`(확정) **둘 다** 저장. 파서 버그를 고치면 `raw_text`로 재파생 가능.

### 4.6 프로토타입 스텁 설계

**두 모드를 UI에 명시한다**

| 모드 | 이미지 | bbox 하이라이트 | 배너 |
|---|---|---|---|
| **데모 스캔** (S1/S2/S3) | 인라인 SVG로 그린 가짜 결과지 | **있음** (좌표 하드코딩) | `STUB · 데모 결과입니다` |
| **내 사진** | 실제 업로드 이미지 | **없음** (팬/줌만) | `STUB · 실제 사진을 읽은 게 아닙니다` |

> **[결정]** 내 사진에 bbox를 그리면 **엉뚱한 위치에 박스가 찍힌다** — 박스 없는 것보다 나쁘다. `P04`는 앱 전체의 신뢰 축이므로 여기서 거짓말하면 안 된다.
> **[결정]** 데스크톱 인터랙션(휠 줌, 드래그 팬)을 **반드시** 넣는다. 오너는 노트북에서 검증한다. 핀치줌/더블탭만 있으면 뷰어가 죽는다.

**가짜 파이프라인** (`P11-F07`로 3초/12초/25초 전환, 각 단계 ±20% 지터)

| 단계 | 문구 | FAST 소요 |
|---|---|---|
| 1 | 사진 불러오는 중… | 200ms |
| 2 | 기울기·밝기 보정 중… | 600ms |
| 3 | 문자 인식 중… | 1,200ms |
| 4 | 항목 추출 중… | 700ms |
| 5 | 값 검증 중… | 400ms |

`P03-B08 취소`는 **실제로 동작해야 한다**(`AbortSignal`). v1에서 필요한 경로다.

**내장 샘플 3종** — 전부 `extractInBody`를 거쳐 같은 지연·같은 검토 화면으로. 특별 취급 없음.

| ID | 이름 | 목적 | 심어둔 문제 | 전제 |
|---|---|---|---|---|
| **S1** | 깨끗한 A4 (InBody 570) | 해피 패스 | 없음. 전부 🟢, 버튼 한 번 확정 | 없음 |
| **S2** | 헬스장 영수증 (270 감열지) | 노랑 흐름 | SMM `confidence 0.72`(raw_text에 눈금 미끼 포함), 측정일시 일부 잘림 → EXIF 대체, 부위별/VFA 없음 | 없음 |
| **S3** | 빛 반사 + 기울어진 사진 | **빨강 + 제안 + 이상치** | 체중 `634`(hard 범위 이탈 → T4 제안 63.4), PBF `2.21`(C2 위반 → **파생 제안 27.1**), 체중 확정 후 S1 대비 T3 경고 발화 | **S1을 먼저 확정해야 함** |

> **[결정]** 원안 S3는 체중을 `null`로 두면서 동시에 C2 위반을 기대했다 — C2는 체중 없이는 평가 자체가 불가하므로 두 결함이 **상호 배타**였고, 제안 칩·이상치 모달이 전부 도달 불가였다. 체중을 `634`(오독)로 바꿔 C2를 평가 가능하게 만들고, 제안 두 종(휴리스틱 63.4, 파생 27.1)을 한 흐름에서 시연한다.
> **S3는 로드 순서 전제가 있다.** `P91-B04` 골든 케이스 로더가 `S1 확정 → S3 로드` 스크립트를 자동 실행한다.

**썸네일**: 실제 사진 파일 대신 **인라인 SVG로 그린 가짜 결과지**(막대그래프·표·한글 라벨). S3는 그 위에 `transform: skewY()` + 흰색 그라디언트 밴드(글레어)를 얹는다. 파일이 가볍고 `file://`에서도 잘 뜬다.

**실제 업로드 경로**
```html
<input type="file" accept="image/jpeg,image/png" id="P03-in-file">                    <!-- B02 파일 선택 -->
<input type="file" accept="image/*" capture="environment" id="P03-in-cam">            <!-- B01 촬영 -->
```
- 실제 썸네일은 `URL.createObjectURL(file)`로 **진짜** 보여준다.
- 그리고 S1~S3 중 하나를 반환한다 + `STUB` 칩 필수 노출.
- **HEIC는 `accept`에서 제외**하고, 확장자/매직넘버로 감지되면 `M03`에서 명시: *"아이폰 HEIC는 지원하지 않습니다. 설정 → 카메라 → 포맷에서 '높은 호환성'으로 바꾸거나 JPG로 변환해주세요."* (브라우저가 디코드하지 못하므로 조용히 실패시키지 않는다.)
- `getUserMedia` 카메라 프리뷰 모달은 **만들지 않는다**(`file://`에서 차단). `capture` 속성으로 대체.

**수동 입력 = 일급 시민**: 동일한 `Extraction` 객체를 만들되 전 필드 `source:"manual", confidence:1.0`. **검토 화면(`P04`)이 곧 입력 폼**이다. 화면 둘이 아니라 코드 경로 하나, 진입점 둘(`P03-B05`, `P04-B13`).

**검증기는 스텁하지 않는다.** T0~T5를 실제 구현한다. 순수 함수라 싸고, 검토 화면이 진짜로 느껴지는 유일한 이유이며, v1에서 한 줄도 안 바뀐다.

### 4.7 개인정보 (P0 기준)

- 인바디 결과지에는 이름·회원ID가 함께 인쇄된다. **추출하지 않고 저장하지 않는다.** 플래너가 쓰지 않는다.
- `P04-B15 이름 가리기` 토글(기본 ON): 업로드 전 canvas에서 상단 헤더 밴드를 검게 덮는다. 단 **측정일시도 같은 밴드에 있으므로, 마스킹 시 날짜를 반드시 사용자에게 확인받는다.**
- **P0는 네트워크 요청 0건이며 그 사실을 화면에 쓴다**(`P03-C05`):
  > `이 프로토타입은 사진을 어디에도 보내지 않습니다. 모든 데이터는 이 브라우저에만 저장돼요.`
  이 한 줄이 없으면 검증 피드백이 기능 얘기 대신 "이거 내 사진 어디로 가요?"로 오염된다.
- 스캔 관련 화면에 **서드파티 스크립트 0개, 애널리틱스 0개, CDN 폰트 0개.**
- **전체 내보내기(`M29`) / 전체 삭제(`M26`)는 협상 대상이 아니다.**
- v1 프록시 요구사항(참고): API 키는 서버 환경변수 · **요청 본문 로깅 금지** · 저장 금지 · EXIF 제거 · 레이트리밋. UI 문구는 **실제 제공자 정책을 확인한 뒤** 확정한다 — 지키지 못할 약속을 쓰지 않는다.

## 5. 고유번호(UID) 체계

### 5.1 taxonomy

| 접두 | 의미 | 스코프 | 배지색 | 비고 |
|---|---|---|---|---|
| `P` | Page / 화면 | **전역** | `#6D28D9` | 라우팅 단위 |
| `M` | Modal / 팝업 / 시트 | **전역** | `#BE185D` | 여러 화면에서 열리므로 화면에 종속시키지 않음 |
| `X` | Toast / 스낵바 | **전역** | `#B91C1C` | 공용 컴포넌트 |
| `N` | Nav item | 컨테이너 | `#4338CA` | 셸(`P00`)의 자식 |
| `T` | Tab | 컨테이너 | `#0E7490` | 화면/모달 내부 탭 |
| `B` | Button / 액션 | 컨테이너 | `#1D4ED8` | 아이콘·링크 버튼 포함 |
| `F` | Field / 입력 | 컨테이너 | `#0F766E` | input·select·slider·stepper·toggle |
| `C` | Card / 섹션 | 컨테이너 | `#92400E` | 시각적 블록 경계 |
| `L` | List / Table | 컨테이너 | `#334155` | 반복 렌더 컨테이너 |
| `G` | Graph / Chart | 컨테이너 | `#7E22CE` | 차트·게이지·프로그레스 |
| `S` | Empty / Loading state | 컨테이너 | `#525252` | 빈 상태·진행 상태 |
| `E` | Error state | 컨테이너 | `#9A3412` | 인라인 오류·경고 배너 |

**12종 고정.** 아이콘·라벨·장식 이미지에는 ID를 주지 않는다. ID가 붙은 요소는 "피드백 대상으로서 의미가 있다"는 신호여야 한다. 모든 DOM 노드에 번호를 뿌리면 배지가 노이즈가 되어 시스템 전체가 죽는다.

> **[결정]** 원안 idscheme는 10종(`A`=토스트)이었고 ia-screens는 `X`(토스트)·`S`·`E`를 썼다. **`S`와 `E`를 정식 추가하고 토스트는 `X`로 통일**한다. 빈 상태와 오류 문구는 오너가 가장 많이 지적할 대상이며, 여기에 번호가 없으면 ID 시스템의 절반이 무의미해진다.

### 5.2 스코프 — 하이브리드, 최대 2세그먼트

```
P04-F03     ← 판독 검수 화면의 3번 입력 필드
M12-B04     ← 비현실 목표 경고 모달의 4번 버튼
P00-N03     ← 앱 셸 하단 탭의 3번 항목
X05         ← 전역 토스트 5번
P07-L02#3   ← 플랜 화면 2번 리스트의 3번째 행 (런타임 자동, 레지스트리 미등재)
```

- 컨테이너(`P`, `M`)와 전역 컴포넌트(`X`)는 **전역 2자리 제로패딩 연번**.
- 나머지 리프는 **소속 컨테이너 내부 2자리 연번**, 항상 `컨테이너-리프` 2세그먼트.
- **3세그먼트 금지.** 카드 안의 필드도 `P04-F03`이다. 길어서 말하기 어렵고, 요소를 다른 카드로 옮기면 ID가 바뀌어 안정성 계약을 깬다. 중첩 관계는 레지스트리의 `설명` 컬럼이 알려준다.

**대역**

| 대역 | 용도 |
|---|---|
| `P00` | 앱 셸 |
| `P01`–`P39` | 제품 화면 |
| `P90`–`P99` | 검증/디버그 화면 |
| `M01`–`M89` | 제품 모달 |
| `M90`–`M99` | 피드백 시스템 모달 |
| `X01`–`X89` | 제품 토스트 |
| `X90`–`X99` | 피드백 시스템 토스트 |

> **[결정]** 원안은 "번호 예약 금지"(§4.1 규칙 8)와 "대역 예약표"(§1.5)를 동시에 주장했고, 핵심 대역이 9개뿐이라 화면 13개를 수용하지 못했다. **예약 금지는 리프 번호에만 적용**하고, 컨테이너는 위 대역을 유지하되 제품 화면 대역을 `P01–P39`로 넓힌다.

### 5.3 반복 행

리스트는 컨테이너 `L`에만 ID를 주고, 행 인스턴스는 런타임이 `#n`을 붙인다. `#n`은 레지스트리에 등록하지 않는다(데이터 개수에 따라 변하므로).

**행 내부의 반복 버튼**은 복사 문자열에 소속 행 정보를 실어 구분한다:
```
P07-L02#3 / 인클라인 덤벨 프레스 · P07-B02 종목 교체
```
> **[결정]** 원안은 "라벨이 같이 실려 구분된다"고 주장했지만 복사 코드는 `${id} / ${label}`만 만들었다. 3세그먼트 복사 문자열을 **실제로 구현**한다.

**같은 ID를 여러 실물 요소가 공유하는 경우 처리**
- `P05`의 ±스테퍼처럼 필드마다 반복되는 버튼은 **필드별 개별 번호**(`P05-B01`~`B08`)로 분리한다.
- `M13`의 "이 강도 선택" 3개 CTA는 `M13-B01/B02/B03`으로 분리한다.
- 삭제 확인 모달은 용도별로 `M25`/`M26`/`M27`/`M28`로 분리했다(§2.4).
- 진짜 반복(리스트 행 내부)은 레지스트리에 `repeat: true`를 표기하고 **드리프트 검사의 `dupes` 판정에서 제외**한다.

### 5.4 배지 렌더링

**실제 `<span>` 주입** (CSS `::after` 아님). 이유: `<input>`/`<canvas>`/`<select>`는 replaced element라 의사요소가 생성되지 않는데, 이 앱은 입력 필드(`F` 50개 이상)와 차트(`G` 15개)가 핵심이다. 또 배지를 **클릭해서 복사**해야 하고, 라벨 확장·메모 카운트 같은 자식 구조가 필요하다.

```html
<span class="uid-badge uid-t-F" data-uid-for="P04-F03" data-uid-pos="tr" aria-hidden="true" tabindex="-1">
  <span class="uid-badge__id">P04-F03</span
  ><span class="uid-badge__label">골격근량</span
  ><span class="uid-badge__count"></span>
</span>
```

| 속성 | 값 | 이유 |
|---|---|---|
| `font-size` | 9px (설정에서 9/10/11) | 6~9자 ID가 판독 가능한 하한 |
| `font-family` | `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` | `0/O`, `1/I` 구분 |
| `font-weight` | 600 | 9px에서 400은 뭉갠다 |
| `font-variant-numeric` | `tabular-nums` | 배지들이 세로로 줄 맞음 |
| `padding` / `radius` | `1px 3px` / `3px` | 총 높이 ~12px |
| **`max-width`** | **없음 (ID는 항상 전체 노출)** | §아래 결정 |

> **[결정 — 치명]** 원안은 평상시 `max-width: 4ch` + `overflow:hidden`이라 `P04-F03`(7자)이 `P04-` 정도로 잘렸고, 확장은 `:hover`에서만 일어나 **모바일에서는 영원히 잘린 채**였다. 오너의 요구사항 원문이 "고유번호 작게 붙여놔"인데 번호가 안 보이면 기능이 0이다. **ID 스팬은 `max-width` 없이 항상 전체 노출**하고, `overflow:hidden` + 폭 트랜지션은 **한글 라벨(`__label`)에만** 적용한다.

**위치**: 컨테이너형(`P M C L G S E`)은 좌상단 바깥(`top:-6px; left:-6px`), 컨트롤형(`B F N T X`)은 우상단 바깥(`top:-5px; right:-5px`). 컨트롤 좌상단은 아이콘/`<label>`이 이미 점유한 자리다.

**클리핑 방지 3중 장치**
1. 셸 루트 `overflow-x: clip` (`hidden`이 아니라 `clip` — `position:sticky`가 안 깨진다)
2. **호스트 기준** 넘침 판정으로 `-in`(요소 안쪽) 전환. **매번 `tl`/`tr`로 리셋 후 재판정**하는 양방향.
3. 중첩 깊이 오프셋 `--uid-dy = depth × 12px`

> **[결정]** 원안 `fitBadges()`는 `r.top < 0`을 뷰포트 기준으로 보고 단방향 래치였다. 스크롤+회전 한 번이면 위쪽 배지가 전부 요소 **안쪽**으로 영구 이동해 카드 제목과 입력 텍스트를 덮는다. 호스트 rect 기준 + 양방향 + 150ms 디바운스로 교체.

**레이아웃 무해성**
- 배지는 항상 `position:absolute`. 호스트는 `getComputedStyle(el).position === 'static'`일 때만 `.uid-anchored{position:relative}` 부여.
- replaced element는 `<span class="uid-wrap" data-uid-host>`로 감싸고 **`display:block; width:100%`를 기본**으로 준다(inline 컨텍스트에서만 `inline-block`).
- 호버 규칙은 `[data-uid]:hover > .uid-badge, [data-uid-host]:hover > .uid-badge` 둘 다 매치해야 한다.

> **[결정]** 원안은 래퍼에 `display:inline-block`(shrink-to-fit)만 주어 `input{width:100%}` 같은 평범한 폼 CSS를 전부 깨뜨렸고, 래퍼에 마커가 없어 **정작 input/canvas에서만 호버 강조가 죽었다**(`::after`를 버린 근거가 바로 그 둘이었는데).
- `auditLayout()`을 **실제로 구현**한다: 배지 주입 전/후 모든 `[data-uid]`의 `getBoundingClientRect()`를 스냅샷 비교해 1px 이상 차이가 나면 콘솔 에러 + `P90-C02`에 보고.

**대비 — 이중 링**
```css
box-shadow: 0 0 0 1px rgba(255,255,255,.70),   /* 어두운 배경에서 분리 */
            0 0 0 2px rgba(0,0,0,.45);          /* 밝은 배경에서 분리 */
```
링 두 개가 항상 함께 있으므로 배경이 흰색이든 검정이든 **인바디 사진 위 오버레이**든 경계가 무너지지 않는다. 다크 모드에서는 알파만 `.55`/`.60`으로 조정하고 순서는 유지(순서를 바꾸면 중간 밝기 배경에서 오히려 나빠진다).

칩 색은 전부 흰 글자 기준 4.5:1 이상(대부분 7:1 이상). **색은 클래스로 부여한다**(`.uid-t-F{--uid-c:var(--uid-F)}`), 인라인 `var()` 참조 금지 — 미정의 타입에서 `--uid-c`가 "설정은 됐으나 해석 불가"가 되어 폴백이 발동하지 않고 `background`가 `transparent`로 떨어진다(흰 글자 + 투명 = 배지 증발). `decorate()`는 미등록 타입에 `console.error`를 찍는다.

**z-index 레이어**: 콘텐츠 배지 100 / 모달 1000 / 모달 내부 배지 1100 / 토스트 2000 / 토스트 배지 2100 / 개발 독 3000. 모달이 열린 동안 `html.uid-modal-open #screens .uid-badge{display:none}`로 **배경 화면 배지를 끈다**(안 그러면 모달 딤 위로 배경 배지 수십 개가 뜬다).

**접근성**: 배지는 **항상 `tabindex="-1"` + `aria-hidden="true"`.** 키보드 접근은 별도 경로로 준다 — `Shift+.` / `Shift+,`로 다음/이전 `[data-uid]` 요소 포커스 + 라이브 리전 ID 안내, 또는 `P90`에서 행 선택 → 점프.
> **[결정]** 원안은 배지 ON일 때 `tabindex=0`으로 승격했다. 기본값이 ON이므로 포커스 가능 요소가 300개 가까이 늘어나 `P04`의 입력 14개를 지나가는 데 Tab을 28번 넘게 눌러야 했고 — 그 화면이 검증 우선순위 1위다 — `aria-hidden=true` 요소에 포커스를 주는 ARIA 위반이기도 했다.

**기타**: `opacity .72` 평상시 → 호스트 호버 시 1.0 + `scale(1.25)` → 배지 호버 시 라벨 펼침 + `cursor: copy`. 메모 있으면 배경 `--uid-X` + `●3` 카운트. `prefers-reduced-motion`에서 모든 트랜지션 제거. `@media print`에서 `display:none`.

### 5.5 파워 기능

**전역 단축키**

| 키 | 동작 |
|---|---|
| `Shift + I` | 배지 표시/숨김 |
| `Shift + F` | 피드백 모드 on/off |
| `Shift + K` | ID 인덱스(`P90`) |
| `Shift + G` | 상태 갤러리(`P91`) |
| `Shift + E` | 피드백 내보내기(`M91`) |
| `Shift + D` | 다크/라이트 전환 |
| `Shift + .` / `,` | 다음/이전 ID 요소로 포커스 |
| `Shift + /` | 단축키 도움말(`M92`) |
| `Escape` | 모달 닫기 → 피드백 모드 해제 순 |

입력 중(`INPUT`/`TEXTAREA`/`contenteditable`)에는 단축키를 무시한다. 단 `Escape`는 항상 받는다.

**배지 클릭 = 복사**
- 클릭 → `P04-B10 / 저장하고 목표 설정` 을 클립보드로. 오너가 붙여넣기만 해도 대상과 명칭이 동시에 전달된다.
- `Alt + 클릭` → 딥링크 URL (`…#P04-B10`, 리스트 행은 `#P07-L02#3`까지 포함)
- `Shift + 클릭` → 메모 작성(`M90`)
- **`file://`은 secure context가 아니라 `navigator.clipboard`가 없다.** `document.execCommand('copy')` 폴백 필수. 그것도 실패하면 텍스트 선택 상태로 남겨 `Ctrl+C`를 유도하고 `X92`를 띄운다.

**ID 복사 모드** (모바일 대응): 개발 독 토글. 켜면 `[data-uid]` 아무 곳이나 탭하면 그 ID가 복사되고 토스트가 뜬다. 배지 자체를 `user-select:all`로 만드는 방식은 **버튼 안에서 동작하지 않는다**(탭이 click을 발사하고, 롱프레스는 컨텍스트 메뉴를 띄운다). 페이지·모달·버튼·필드에 균일하게 작동하는 이 방식이 정답이다.

**피드백 모드** (`Shift+F` / `P00-B03`)
- `[data-uid]`에 `outline: 1px dashed`, `cursor: crosshair`.
- **캡처 단계**에서 클릭을 가로채 `preventDefault` + `stopPropagation` → 제품 동작 없이 메모 팝오버(`M90`)만 열린다. 버블링 단계로는 이미 늦다(버튼 자신의 핸들러가 화면을 넘겨버린다).
- **탈출 면제 목록 (필수)**:
  ```js
  if (e.target.closest('.uid-badge, [data-uid^="M9"], [data-uid^="P00-B"], .uid-dock')) return;
  ```
  더 안전하게는 피드백 시스템 UI에 `data-uid` 대신 `data-uid-sys`를 쓰고 선택자를 `[data-uid]:not([data-uid-sys])`로 좁힌다.
- **`P00-B09` 피드백 모드 종료 고정 배너**를 화면 상단에 띄운다. 이 버튼은 항상 가로채기 면제다.

> **[결정 — 치명]** 원안은 예외 처리가 한 줄도 없어, 피드백 모드를 켜는 순간 메모 textarea 클릭이 "textarea에 대한 새 메모"를 열고, 저장 버튼이 "저장 버튼에 대한 메모"를 열고, 모드 해제 버튼도 안 눌렸다. **피드백을 한 건도 저장할 수 없고 모드에서 나갈 수도 없는** 잠금 상태였다(폰에서는 새로고침 외 탈출 불가).

`- [ ]` 체크박스 형식이므로 오너가 붙여넣으면 그대로 **실행 가능한 할 일 목록**이 되고, 다음 턴에 `- [x]`로 바꿔 돌려줄 수 있다. **미분류 섹션과 폐기 ID 섹션은 필수** — 레지스트리에 없는 요소를 오너가 지적했을 때 피드백이 유실되지 않게 하는 안전망이다.

**딥링크**
- `#P04` → 화면 라우팅. `#P04-F03` → 라우팅 + `scrollIntoView({block:'center'})` + `.uid-flash` 펄스.
- `#M12` → 레지스트리의 `open_from` 화면으로 이동 **후 모달 오픈**.
- `#P07-L02#3` → 행 하이라이트(행이 없으면 리스트 하이라이트 + `X08`).
- `hashchange` 리스너. 대상 미렌더 시 `requestAnimationFrame` 재시도(최대 10회) 후 `X08`.

**스크린샷 규약**: 오너가 화면을 캡처해 보낼 때는 **배지를 켠 상태**로 찍는다. `P00-B02`로 언제든 끌 수 있으며, 끈 상태의 레이아웃은 최종 앱과 동일해야 한다(`auditLayout()`이 보장).

### 5.6 안정성 계약

> **최상위 원칙: 오너가 어제 적어둔 `P07-B04`는 내일도 같은 버튼이다. 번호는 절대 밀리지 않는다.**

1. **한 번 부여된 번호는 영구하다.** 재사용 금지, 재번호 금지.
2. **삭제 = 폐기(retire)**, 행 삭제가 아니다. `status:"retired"`, `retired_in: 3`. 그 번호는 영원히 비어 있다.
3. **추가 = 해당 컨테이너의 다음 빈 정수.** 시각적 위치와 무관. 화면 맨 위에 버튼을 넣어도 `P05-B15`다. 시각 순서와 번호 순서가 어긋나는 것은 **의도된 비용**이며, 그 대가로 오너의 메모가 절대 무효화되지 않는다. 표의 **행 순서**가 시각 순서를 표현한다.
4. **다른 화면으로 이동 = 폐기 + 신규.** 구 행에 `moved_to: "P06-B07"`을 남겨 기존 피드백이 따라가게 한다(내보내기에 `(구 P05-B03에서 이동)` 주석).
5. **라벨 변경은 ID에 영향 없음.** `label_history[]`에 쌓아 옛 이름으로도 `P90`에서 검색된다.
6. **화면 삭제 시 `Pnn`도 폐기.** 화면 번호 재활용은 가장 치명적인 혼동이므로 예외 없다.
7. **`REGISTRY_VERSION` 정수를 라운드마다 +1.** 모든 메모에 기록되어, v1에 쓴 메모를 v4에서 볼 때 "그 사이 폐기됨/이동됨" 경고를 띄운다. **`refreshNoteMarks()`와 `exportMarkdown()`이 `retired`/`moved_to`를 실제로 읽어야 한다.**
8. **번호 예약 금지** — 단, 리프 번호에 한함(컨테이너 대역은 §5.2 표대로).
9. **해결된 메모 아카이브**: 라운드 시작 시 `status:"해결"` 메모를 `mybody.uid.feedback.archive.v1`로 옮긴다(`M91`에 "해결 항목 아카이브" 액션). 3라운드째에 내보내기가 해결 항목으로 뒤덮이는 것을 막는다.

**레지스트리 파일**: `prototype/js/uid-registry.js` — **JS 객체 리터럴**(JSON을 `fetch`하면 `file://`에서 CORS로 막힌다).
```js
window.UID_REGISTRY = {
  version: 1, updated_at: "2026-09-19",
  screens: {
    P04: { label: "판독 검수", kind: "page", order: 5 },
    M12: { label: "비현실 목표 경고", kind: "modal", open_from: "P05" }
  },
  items: [
    { id:"P04-F03", type:"F", screen:"P04", label:"골격근량 SMM (kg)",
      desc:"OCR 인식값, 편집 가능, 0.1 단위", status:"active", since:1, repeat:false },
    { id:"P05-B12", type:"B", screen:"P05", label:"목표 초기화",
      status:"retired", since:1, retired_in:3, moved_to:null, note:"M12에 흡수" }
  ]
};
// CHANGELOG
// v1 (2026-09-19): 최초 작성
```

**드리프트 감사** (`P90-B03`, 부팅 시 자동): DOM 실측 ↔ 레지스트리 대조 3종 리포트
- `unreg` — DOM엔 있고 레지스트리엔 없음
- `missing` — 레지스트리 `active`인데 DOM에 없음 (단 `kind:"toast"`와 `repeat:true`는 제외)
- `dupes` — 같은 ID 2개 이상 (단 `data-uid-index` 보유 요소와 `repeat:true`는 제외)

빌드 시스템이 없으므로 **런타임 감사가 CI 역할**을 한다. 레지스트리 갱신은 화면 코드 수정과 **같은 커밋**에서 이뤄져야 하며, 이를 지키게 하는 장치가 이 감사다.

**반복 주기**: ① 오너 `Shift+E` → 마크다운 붙여넣기 → ② 반영(삭제는 `retired`, 신규는 다음 빈 번호, `version`+1) → ③ `CHANGELOG` 주석에 `v2: P05-B12 폐기, P05-F11 신규` → ④ 오너는 `P90`에서 "이번에 바뀐 ID"만 필터해 확인.

### 7.1 파일 구조

```

├─ index.html                 ← 전 화면·모달·토스트 마크업. 배지는 JS가 주입
├─ css/
│  ├─ base.css                ← 리셋·토큰·레이아웃·다크모드
│  ├─ components.css          ← 카드/버튼/필드/차트/모달/토스트
│  └─ uid.css                 ← 배지 시스템 (§5.4)
└─ js/
   ├─ constants.js            ← ENGINE_CONSTANTS + validateConstants()
   ├─ schema.js               ← ★ 필드 정의 단일 테이블 (라벨·단위·범위·필수·표시순서)
   ├─ calc.js                 ← 파생 수식. DOM·저장소 모름
   ├─ engine.js               ← 에너지·분류·실현가능성·매크로·볼륨·교환배정. 순수 함수
   ├─ validate.js             ← T0~T5. 순수 함수. v1까지 무변경
   ├─ extractor.js            ← extractInBody() 스텁 + 단계별 지연 + AbortSignal
   ├─ samples.js              ← S1/S2/S3 Extraction 리터럴 + SVG 썸네일
   ├─ catalog-exercise.js     ← 종목 시드 (패턴 7종 × 장비 3종, 최소 40종목)
   ├─ catalog-food.js         ← 한식 교환표 시드 + 슬롯 템플릿 + 외식/편의점 조합표

   ├─ router.js               ← 해시 라우팅 + 모달 스택 + 포커스 트랩

   ├─ render.js               ← 화면 렌더. 계산 결과만 받아 그린다
   ├─ app.js                  ← 상태·이벤트 배선
   ├─ uid-registry.js         ← §6 레지스트리 객체 리터럴 + CHANGELOG 주석
   ├─ uid.js                  ← 배지 주입·복사·피드백 모드·딥링크·드리프트 감사
```

> **[결정 — `file://` 제약]** **ES 모듈(`type="module"`)을 쓰지 않는다.** `file://`에서 CORS로 차단된다. 전부 고전 `<script src>` + 전역 네임스페이스(`window.MB.engine`, `window.MB.validate` …). "계산 로직이 DOM·저장소를 모른다"는 원칙은 파일 분리와 IIFE만으로 충분히 지킬 수 있다. 모듈화는 백엔드 전환 시점으로 미룬다.
> 같은 이유로 **`fetch('./*.json')`도 금지**. 샘플·레지스트리·카탈로그는 전부 JS 객체 리터럴이다.

**`schema.js`가 이 설계의 중심**이다. 필드의 **한글 라벨·단위·hard/soft 범위·필수 여부·표시 순서·UID**를 한 곳에서 정의하고, 검증기·검토 화면·수동 입력 폼·용어 사전이 전부 거기서 읽는다. 항목 하나 추가가 한 줄 추가가 되어야 한다.

> **[결정 — 치명]** **이미지는 IndexedDB에 Blob으로 저장한다.** localStorage는 오리진당 약 5MB이고 문자열을 UTF-16으로 센다 — 3MB 사진의 dataURL(~4M자)은 쿼터에서 ~8MB를 먹어 **첫 업로드에서 터진다.** localStorage에는 메타데이터와 400px 썸네일(canvas 리사이즈, ~40KB)만 둔다.
- 썸네일: 장변 400px, JPEG q0.7. 원본 Blob: 장변 1600px 재인코딩(용량 절감 + EXIF 제거 부수효과).
- 보관: 원본은 **최대 3장**. 초과 시 오래된 것부터 삭제(수치는 유지), 삭제 전 `M27` 확인.
- 모든 읽기/쓰기는 `try/catch`. `localStorage` 접근 자체가 throw하면 **메모리 Map으로 자동 강등(degraded mode)** 하고 `P00-C04` 배너를 띄운다.
- `QuotaExceededError` → `M27`. 미래 버전 감지 → `M28`.

**접근 계층 필수 패턴**: DOM에서 직접 `localStorage`를 부르지 않는다. 반드시 `DB`/`Repo` 경유 → 나중에 `Repo`만 `fetch`로 갈아끼우면 끝.

## 8. 알려진 한계 / 검증받고 싶은 질문

### 8.1 알려진 한계 (의도적으로 남김)

1. **`k_user`(SMM/FFM 비)가 근성장 판정 전체를 좌우한다.** 실제 InBody 추적 데이터로 보정하기 전까지 모든 증근 기간 추정에 ±40% 불확실성이 있다. 증근 속도 문헌은 대부분 LBM/FFM 기준인데 사용자는 SMM 목표를 입력하기 때문이다. 우리는 보수적으로 변환한다.
2. **증근 속도표는 관찰 기반 실무 모델**이지 RCT 메타분석이 아니다. 반응자/비반응자 편차가 크다.
3. **선형 에너지 모델(7,700 kcal/kg)은 장기에서 감량을 과대추정한다.** 적응형 TDEE가 2주 뒤 흡수하지만 첫 계획의 예측 곡선은 낙관적이다 → ±20% 밴드를 반드시 표시한다.
4. **순응도는 모델에 없다.** 엔진은 "완벽히 지켰을 때"를 계산하고 `expected_adherence_pct`로 할인할 뿐이다. 실제 결과는 §3.13의 관측값이 유일한 진실이다.
5. **부위별 BIA로 국소 지방 감소를 계획하지 않는다.** spot reduction은 근거가 없다.
6. **여성 사용자의 월경 주기 수분 변동·경구피임약 영향은 v0.1에서 모델링하지 않는다.** 조정 보류 규칙으로만 대응한다.
7. **InBody 모델별 항목 차이**를 완전히 매핑하지 못했다. 파서는 "있으면 읽고 없으면 null"로만 동작한다.
8. **교환단위 배정은 ±5% 오차를 남긴다.** 정수 교환의 한계이며 오차를 화면에 그대로 표시한다.
9. **`P08` 주간 재조정의 임계값은 추정**이다. 실제 오너 데이터 4~8주를 모아야 표준오차 기반 임계가 의미를 갖는다.
10. **프로토타입의 숫자는 전부 스텁 판독에서 나온다.** "내 골격근량을 잘못 읽었다"는 피드백은 무의미하다 — `STUB` 칩이 그 점을 화면에 밝힌다.
