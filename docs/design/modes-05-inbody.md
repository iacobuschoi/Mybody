# InBody 신뢰도 스윕 — 모드 자동선택이 실제로 딛고 설 수 있는 지반

**담당 범위:** InBody 수치가 모드 판정에 쓸 만한가. 임계값은 얼마여야 하는가. 오너의 실제 궤적은 진짜인가.

## 0. 출처에 대한 정직한 고지 (먼저 읽을 것)

이 세션의 egress 프록시가 **거의 모든 학술 도메인에 대한 직접 fetch를 차단**했습니다 (`pmc.ncbi.nlm.nih.gov`, `frontiersin.org`, `mdpi.com`, `nature.com`, `journals.plos.org`, `en.wikipedia.org`, `inbody.com`, `strongerbyscience.com`, `macrofactor.com`, `namu.wiki` 전부 403). 확인: `curl -sS "$HTTPS_PROXY/__agentproxy/status"` → `connect_rejected / policy denial`.

따라서 아래 표기를 구분해서 읽어야 합니다:

| 표기 | 의미 |
|---|---|
| `[검색요약]` | WebSearch가 반환한 해당 논문의 요약에서 나온 수치. 논문 원문을 직접 읽지 못했음. 초록 수준의 신뢰도로 취급할 것 |

**이 보고서의 핵심 결론들은 `[유도]` 에 기대고 있습니다.** 외부 논문은 보조 근거입니다. 그게 이 보고서의 가장 단단한 부분인 게 다행이기도 합니다 — 오너의 결과지 한 장으로 InBody의 내부 공식을 **전부 정확히 재현**했기 때문입니다.

## 1. 먼저, 구조적 사실 하나 — 체지방량은 "측정"되지 않는다

이게 나머지 전부를 지배합니다. 오너의 2026-09-19 시트로 검증했습니다.

```
TBW 48.7 + 단백질 13.3 + 무기질 4.70 = 66.70  →  시트의 FFM 66.7   ✓ 정확히 일치
TBW 48.7 / 0.73                      = 66.71  →  시트의 FFM 66.7   ✓ 정확히 일치
체중 86.7 − FFM 66.7                  = 20.0   →  시트의 BFM 20.0   ✓ 정확히 일치
370 + 21.6 × 66.7                     = 1810.7 →  시트의 BMR 1810   ✓ 정확히 일치 (Katch-McArdle)
```

즉 InBody 270이 실제로 **재는** 것은 임피던스 → 거기서 **체수분(TBW)** 하나를 추정하고, 나머지는 전부 산수입니다:

```
임피던스 → TBW → FFM = TBW/0.73 → BFM = 체중 − FFM → PBF = BFM/체중
                          ↓
                        SMM (사지 임피던스 기반 별도 회귀식)
```

**[유도] 레버리지 계산 — 이 보고서에서 제일 중요한 숫자 하나:**

> TBW 추정이 **1 L** 틀리면
> → FFM이 **1.37 kg** 틀리고
> → BFM이 **1.37 kg** (반대 부호로) 틀리고
> → PBF가 **1.58 %p** 틀린다.

체수분 1리터는 물 한 병입니다. 훈련 후 글리코겐 적재, 짠 음식, 아침/점심 차이로 **일상적으로** 움직이는 양입니다. 그게 "체지방 1.4 kg"으로 증폭되어 결과지에 찍힙니다.

**앱 설계에 주는 함의 3가지:**

1. **체중만이 진짜 측정값이다.** 저울은 ±0.1 kg. BFM·SMM·PBF는 전부 파생값이고 전부 TBW 오차를 물려받습니다.
2. **BFM 변화량과 FFM 변화량은 독립 정보가 아니다.** `ΔBFM = Δ체중 − ΔFFM`. 수학적으로 완전 종속입니다. 모드 판정 로직이 Δ근육과 Δ지방을 "두 개의 증거"처럼 취급하면 **같은 오차를 두 번 세는 것**입니다.
3. **0.73은 상수로 박혀 있다.** 체지방률이 높을수록 실제 제지방 수화도가 77% 이상으로 올라간다는 보고가 있고[검색요약], 그러면 InBody는 FFM을 계통적으로 과대평가합니다. 오너처럼 PBF 28% → 23%로 내려가는 동안 실제 수화도가 함께 내려갔다면, **그 변화만으로 FFM이 늘어난 것처럼 보입니다.** (아래 8절에서 정량화)

### 2.3 **변화량**을 추적할 때 — 여기가 우리에게 중요한 부분

|---|---|
| InBody 770 vs DXA, 4주 저열량식 (훈련된 성인) [검색요약] | 기저값은 편향돼 있었으나, **4주간의 FM·FFM·체지방률 변화량에서는 두 기기 간 통계적 유의차 없음.** 4주 중재 추적에는 DEXA 대체 가능하다고 결론 |
| 대학 미식축구 선수 비시즌, DXA vs MF-BIA [검색요약] | 변화 추적 비교 연구 존재 |
| 미 해병 795명, InBody 770 vs DEXA [검색요약] | **R² = 0.96**, 두 기기 차이는 **무작위가 아니라 계통적** → 개인 추세 추적에는 신뢰 가능 |

**이게 앱에 주는 결정적 함의입니다:**

> **앱은 InBody가 "정확"할 필요가 없다. "일관되게 틀릴" 필요가 있을 뿐이다.**
>
> 모드 선택은 **같은 기계의 델타**로 돌아갑니다. FFM +2.8 kg 같은 계통 편향은 뺄셈에서 **상쇄됩니다**. 남는 건 무작위 성분 — 즉 2.4절의 생물학적 변동입니다.

따라서 흔히 인용되는 "InBody로 체지방 감소를 확신하려면 2.4 kg 이상 움직여야 한다"류의 MDC 수치[검색요약, physiqonomics]는 **우리 앱에는 과하게 보수적인 잘못된 기준**입니다. 저 숫자는 *DEXA 참값 대비* 오차라서 상쇄되는 편향까지 포함하고 있습니다. 우리에게 맞는 기준은 **InBody↔InBody 일간 변동**이고, 그건 훨씬 작습니다 (7절).

### 2.4 오너 기기 — InBody 270의 추가 핸디캡

- InBody 270은 **2주파(20 kHz / 100 kHz)** 로 5부위 × 2 = 10회 임피던스 측정[검색요약]. InBody 770은 **1 kHz~1 MHz 다주파**로 세포내수분(ICW)/세포외수분(ECW)을 분리 측정[검색요약].
- **결과: 270은 ECW/TBW 비를 내주지 않습니다.** 오너 시트(`data.js`)에도 TBW 48.7 L 단일값만 있고 ICW/ECW 분해가 없습니다 — 270 출력 사양과 일치.
- ECW/TBW는 정상 **0.36–0.39**, **≥0.40이면 염증성 체액 이동·부종**을 시사합니다[검색요약].
- **즉 오너는 "이번 근육량 증가는 부종이다"를 알려주는 바로 그 지표를 볼 수 없습니다.** 위 2.1~2.3의 좋은 숫자들은 대부분 **770**에서 나온 것이고, 270은 그보다 나쁠 가능성이 높습니다[미검증 — 270 직접 검증 연구를 찾지 못함. 근거: 주파수 수가 적을수록 수분 구획 분해능이 낮다는 원리].

→ **앱은 이 한계를 UI에서 인정해야 합니다.** "270은 부종 지표가 없어서, 근육량 급증이 진짜인지 물인지 기계가 구분해 주지 못합니다. 그래서 이 앱이 시간 규칙으로 대신 걸러냅니다."

### 3.1 글리코겐 → PBF 로 가는 경로를 끝까지 계산

**[유도]** 이 체인이 앱이 반드시 이해해야 할 메커니즘입니다:

```
훈련량 증가 → 근글리코겐 +300 g
            → 결합수 +0.9~1.2 kg  (1:3~4)
            → TBW +1.0 L
            → FFM +1.37 kg   ← "근육 늘었다!"
            → BFM −1.37 kg   ← "지방 빠졌다!"   (체중 불변 시)
            → PBF −1.58 %p
```

**체중이 1 g도 안 변했는데 결과지는 "근육 +1.4 kg, 지방 −1.4 kg, 체지방률 −1.6%p" 라는 완벽한 리컴프를 보여줍니다.** 단순히 탄수를 더 먹고 운동량을 늘렸을 뿐인데.

이게 헬스장에서 "리컴프 성공했다"는 스크린샷이 그렇게 많은 이유의 상당 부분입니다.

## 4. Q3 — 왜 운동 시작 2~4주에 SMM이 점프하는가

세 가지가 **동시에** 같은 방향으로 작용합니다. 전부 물입니다.

**(1) 손상 유발 부종 (edema-induced swelling)**
Damas et al., *Eur J Appl Physiol* 2016, "Early resistance training-induced increases in muscle cross-sectional area are concomitant with edema-induced muscle swelling" [검색요약]:
> 미훈련 남성 10명. 외측광근 CSA가 **3주차 +2.7%**, **10주차 +10.4%** 증가. 그러나 초기 증가는 **순수 비대가 아니라 근손상으로 인한 부종성 종창이 큰 비중**을 차지.
> 관련 연구: **훈련 4회 이하 시점의 CSA 증가는 대부분 손상성 종창**, 약 **10회 세션 이후** 완만한 실제 비대가 시작.

**(2) 글리코겐 적재**
훈련을 시작하면 근글리코겐 저장 용량과 실제 적재량이 함께 올라갑니다. 3.1절의 체인 그대로 FFM으로 계상됩니다.

**(3) 혈장량 증가**
훈련 초기 적응. 한국 자료에서도 동일하게 지적됩니다 — "글리코겐 저장 증가 / 일시적 붓기 / 혈장량 증가"[검색요약, 국내 의료·헬스 콘텐츠 다수]. 국내 헬스 담론에서도 "인바디는 체수분을 근육으로 인식한다"는 인식은 널리 퍼져 있습니다[검색요약, 몬스터짐·블라인드 헬스판 등].

### 4.1 **그래서 SMM 변화는 언제부터 믿을 수 있나**

| 경과 | SMM 변화의 해석 | 앱의 처리 |
|---|---|---|
| ~3주 | **대부분 물.** 부종 + 글리코겐 | SMM 변화를 **무시**. "근육이 아니라 물입니다" 명시 |
| 3–8주 | 물 성분이 잦아들고 실제 비대가 섞이기 시작 | SMM을 **보되 단독 판정 금지**. 체중 추세와 교차검증 |
| **8주+** | 물 성분이 정상 상태에 도달 (새 baseline). 이후 변화는 실제 조직에 가까움 | SMM 델타를 **모드 판정에 정식 투입** |
| 12주+ | 3점 이상 회귀 기울기 사용 가능 | 기울기 기반 판정 |

**따라서 앱의 하드 규칙:**
> **훈련 시작(또는 프로그램 대폭 변경) 후 8주 미만이면, SMM 증가는 모드 판정 근거로 쓰지 않는다.**
> 8주 미만 구간에서는 체중 추세 + PBF 방향만으로 판정하고, 화면에 이유를 적는다.

이건 임계값으로 못 막습니다. 초기 물 증가는 **임계값을 훌쩍 넘는 크기**(1–2 kg)로 오기 때문입니다. **시간 게이트가 필요합니다.**

## 5. Q4 — InBody의 적정체중·체중조절·지방조절·근육조절

### 5.1 공식을 완전히 역산했습니다 (오너 시트로 100% 재현)

**[유도]** 오너 시트의 모든 파생값을 정확히 재현했습니다:

```
표준체중 SW   = BMI 22 × 키(m)²  = 22 × 1.87²        = 76.93 kg
   검증 → 시트 체중 정상범위 [65.4, 88.4] = SW × [0.85, 1.15] = [65.4, 88.5]  ✓
   검증 → 시트 비만도 113% = 86.7 / 76.93 = 112.7%                            ✓

표준 FFM     = SW × 0.85 = 65.39 kg   (남성 목표 체지방률 15% ⇒ 제지방 85%)
   검증 → 시트 FFM 정상범위 [58.9, 71.9] = 65.39 × [0.90, 1.10]              ✓
   검증 → 시트 TBW 범위 [43.3, 52.9] = (65.39×0.73) × [0.90, 1.10]           ✓
   검증 → 시트 단백질 범위 [11.6, 14.2] ≈ 표준단백질 × [0.90, 1.10]           ✓
   검증 → 시트 무기질 범위 [4.00, 4.89] ≈ 표준무기질 × [0.90, 1.10]           ✓

적정체중      = 현재 FFM / 0.85 = 66.7 / 0.85 = 78.47  → 시트 78.4 kg        ✓
체중조절      = 78.4 − 86.7 = −8.3 kg                  → 시트 −8.3 kg        ✓
지방조절      = 78.4 × 0.15 − 20.0 = −8.24            → 시트 −8.3 kg        ✓
근육조절      = 0.0  (FFM을 고정해서 푼 결과이므로 항상 0)                   ✓

InBody 점수   = 80 + (FFM − 표준FFM) − (BFM − 표준BFM)
              = 80 + (66.7 − 65.39) − (20.0 − 11.54) = 72.8  → 시트 73       ✓
```

InBody 공식 문서와도 일치합니다: 남성 목표 체지방률 **15%**(제지방 85%), 여성 **23%**(제지방 77%); 표준체중은 BMI **22**(남)/**21.5**(여); InBody 점수는 **80점 기준, 초과 근육 1 kg당 +1점, 초과 지방 1 kg당 −1점**[검색요약, InBody USA / LookinBody FAQ].

### 5.2 그래서 — 이 목표는 쓸 만한가? **아니요. 세 가지 이유로.**

**① 근육조절 0.0 kg 은 조언이 아니라 공식의 산물입니다.**

적정체중을 `현재 FFM / 0.85`로 정의한 순간 **FFM은 고정 상수로 들어갑니다.** 그러니 근육조절은 **구조적으로 0이 나올 수밖에 없습니다.** InBody는 오너에게 "근육은 지금으로 충분하다"고 말한 적이 없습니다. 애초에 근육 증량을 권고할 수 있는 형태의 계산이 아닙니다.

> **오너에게 보여줄 한 줄:** "근육조절 0.0 kg은 '근육 그대로 두세요'가 아닙니다. 인바디가 '지금 근육 그대로라고 치고 지방만 빼면 몇 kg?'을 계산한 결과라서 자동으로 0이 됩니다."

**② 목표가 움직이는 표적입니다.**

**[유도]** 적정체중이 현재 FFM의 함수이므로:

| 시나리오 | FFM | 적정체중 |
|---|---|---|
| 지금 | 66.7 | 78.4 kg |
| 근육 +2 kg 성공 | 68.7 | **80.8 kg** |
| 근육 +4 kg 성공 | 70.7 | **83.2 kg** |
| 다이어트로 근육 −2 kg 손실 | 64.7 | **76.1 kg** ← 근손실하면 목표가 "좋아짐" |

**마지막 줄이 이 지표의 치명상입니다. 근육을 잃으면 적정체중이 내려가서 목표에 더 가까워 보입니다.** 이 숫자에 모드를 앵커링하면, 앱이 근손실을 진전으로 보상하게 됩니다.

**③ 15%는 오너의 목표가 아니라 InBody의 기본값입니다.**

22세 남성이 "몸 만들기"를 하려면 보통 12~15%를 봅니다. 우연히 비슷하지만, 그건 우연입니다. 여성 23%는 더 임의적입니다.

### 5.3 **권장섭취칼로리 3104 kcal — 이건 반드시 무시해야 합니다**

**[유도]** `3104 / 1810 = 1.715`. 즉 InBody는 **PAL 1.715**를 가정하고 있습니다. 앱 엔진의 `moderate` = PAL 1.55 → TDEE 2806.

> **차이 298 kcal/day.** 3개월이면 약 **26,800 kcal ≈ 지방 3.5 kg** 만큼의 계획 오차입니다.

InBody의 권장섭취칼로리는 오너의 실제 활동량을 모릅니다. **앱은 자체 TDEE를 쓰고, 실측 체중 추세로 역보정해야 합니다.**

### 5.4 앱의 정책 — 결론

| InBody 항목 | 앱의 처리 |
|---|---|
| 체중, TBW, SMM, BFM, PBF, 임피던스 | **입력으로 사용** (델타 위주) |
| BMR 1810 | **그대로 사용 OK** — Katch-McArdle과 정확히 동일 [유도]. 엔진과 충돌 없음 |
| 적정체중 78.4 | **참고로만 표시, 목표로 앵커링 금지** |
| 체중조절 / 지방조절 −8.3 | **참고 표시**. "근육을 하나도 못 늘린다는 가정의 숫자" 캡션 필수 |
| 근육조절 0.0 | **표시하되 반드시 해설**. 안 그러면 오너가 "근육은 됐다"로 오독 |
| 권장섭취칼로리 3104 | **사용 금지.** PAL 1.715 가정 [유도] |
| InBody 점수 73 | 동기부여용 단일 지표로는 OK. **단 근육 1 kg = 지방 1 kg으로 등가 취급**하는 공식이라 리컴프 중에는 거의 안 움직임 — 오너가 정체됐다고 오해할 수 있으니 주의 |

## 6. Q5 — 표준화 프로토콜

### 6.1 근거

- InBody 공식 계열 가이드: **측정 3–4시간 전 금식** (일부 프로토콜은 8시간 야간 금식), **소변 비우기**, **전날 정상 수분 섭취 유지 — 과수분은 근육량을 과대평가**, **측정 중 움직이거나 말하지 않기**, **공복 상태 아침이 최적, 4주 간격, 가능하면 같은 시간대**[검색요약, InBody Asia / InBody 테스트 가이드라인]
- **중·고강도 운동 후 수 시간은 BIA 측정 금지**[검색요약]
- 국내 자료도 동일: "가급적 운동 전, 매번 아침 공복, 일관된 조건"[검색요약]

### 6.2 앱에 넣을 한국어 카피 (그대로 써도 됩니다)

> **📏 인바디 잴 때 이것만 지켜주세요 — 안 지키면 앱이 헛다리 짚습니다**
>
> 1. **같은 시간대.** 가능하면 아침. (오전 7시 vs 오전 11시만 달라도 근육량이 1 kg 다르게 나옵니다)
> 2. **공복 3~4시간.** 물도 포함. 아침 첫 스캔이 제일 좋습니다.
> 3. **화장실 먼저.** 소변이 지방으로 계산됩니다.
> 4. **운동 전에.** 운동 직후는 절대 금지. 최소 몇 시간 뒤에.
> 5. **전날 평소대로.** 전날 폭식·라면·술·탄수 몰아먹기 → 물 1~2 kg이 근육으로 찍힙니다.
> 6. **같은 기계.** 기계가 바뀌면 이전 기록과 비교 불가.
> 7. **사우나·반신욕 직후 금지.**
> 8. **간격은 최소 4주.** 2주 간격은 잡음만 봅니다.

### 6.3 표준화를 "믿지 말고 기록"해야 합니다

오너는 이걸 다 지키지 않을 것이고, 앱은 그걸 알아야 합니다. **스캔 등록 시 체크리스트를 받고, 그 결과로 임계값을 바꾸세요:**

## 7. Q6 — 모드 판정을 트리거할 최소 유의 델타

### 7.1 어느 통계를 쓸 것인가

표준 LSC(Least Significant Change) = **2.77 × 정밀도 오차**, 95% 신뢰[검색요약, ISCD]. 하지만 95%는 **이 앱에는 과합니다** — "확실히 변했다"를 증명하는 게 아니라 "어느 모드가 더 그럴듯한가"를 고르는 문제이기 때문입니다. 95% 기준을 쓰면 거의 항상 "유지"가 나와서 앱이 쓸모없어집니다.

**제안: 두 단계 임계값.**

- **T_noise** (≈68%, 1σ): 이 아래는 **"변화 없음 = 유지"**. 거짓말하지 않기 위한 하한.
- **T_confident** (≈95%, 2.77σ): 이 위는 **"확실"** 배지. 사이 구간은 판정하되 **"잠정"** 표시.

### 7.2 임계값 표 (86.7 kg 남성 기준, 8주 간격 2회 스캔)

| 지표 | **A: 엄격 표준화** T_noise / T_confident | **B: 실사용 기본** T_noise / T_confident |
|---|---|---|
| 체중 | **0.4** / 1.1 kg | **0.8** / 1.9 kg |
| BFM | **0.5** / 1.4 kg | **1.0** / 2.8 kg |
| SMM | **0.3** / 0.8 kg | **0.6** / 1.7 kg |
| PBF | **0.6** / 1.7 %p | **1.2** / 3.3 %p |

**[유도]** 3.2절의 1σ에 2.77을 곱해 T_confident 산출. 체중은 %BW 스케일이므로 다른 체중의 사용자에게는 비례 조정 필요: `T ∝ 체중/86.7` (SMM·BFM·체중), PBF는 절대 %p 유지.

**참고로, 흔히 인용되는 MDC (vs DEXA 참값, 95%)**: 체지방률 **2.7 %p**, FM **2.4 kg**, FFM **2.3 kg**[검색요약, physiqonomics]. 우리 B열 T_confident와 비슷한 크기라서 **서로를 교차검증해 줍니다.** 다만 2.1절에서 논증했듯 계통 편향이 상쇄되는 우리 용도에는 B열이 더 적절합니다.

### 7.3 임계값만으로는 부족합니다 — 판정 규칙 전체

```
INPUT: scans[], trainingStartDate, dailyWeightLog?

GATE 1 — 간격
  마지막 두 스캔 간격 < 28일  ⇒ 모드 판정 안 함.
     "아직 4주가 안 됐습니다. 지금 차이는 대부분 수분입니다."

GATE 2 — 훈련 경과 (SMM 전용)
  훈련 시작 < 8주  ⇒ ΔSMM을 판정에서 제외. 체중 추세 + ΔPBF만 사용.
     "운동 시작 초기 근육량 증가는 대부분 글리코겐과 부종입니다."

GATE 3 — 노이즈
  |Δ| < T_noise 인 항목은 0으로 간주.
  세 항목 모두 0  ⇒  모드 = 유지

GATE 4 — 추세 우선
  스캔 ≥ 3개 & 기간 ≥ 8주  ⇒  2점 델타 대신 선형회귀 기울기 사용.
     훨씬 강건함. 기울기 신뢰구간이 0을 포함하면 그 항목은 0.

GATE 5 — 체중은 저울 추세로 대체
  일일 체중 로그가 있으면 InBody 체중 대신 7일 이동평균 회귀 기울기 사용.
     표본이 많아 노이즈가 √n로 줄어듦. 이게 제일 신뢰도 높은 신호.

GATE 6 — 종속성 교정 (중요)
  ΔBFM = Δ체중 − ΔFFM 이므로 독립 증거가 아님.
  ⇒ 판정 가중치: 체중 추세 최우선, PBF 차선, SMM 최하위.
     Δ근육과 Δ지방을 동등 가중하면 같은 오차를 두 번 셈.
```

### 7.4 모드 자동선택에 넘기는 신호 순위 (신뢰도 순)

| 순위 | 신호 | 노이즈 | 비고 |
|---|---|---|---|
| 1 | **일일 체중 7일 이동평균 기울기** | 매우 낮음 | 가능하면 무조건 이것부터 |
| 2 | **InBody 체중 델타** | 낮음 | 유일한 실측값 |
| 3 | **ΔPBF** | 중간 | 방향은 믿을 만함, 크기는 부풀려짐 |
| 4 | **ΔBFM** | 중간 | PBF와 거의 중복 정보 |
| 5 | **ΔSMM** | 높음 | 8주 게이트 필수. 단독 판정 금지 |
| — | **현재 PBF (절대값)** | 편향되나 안정적 | **감량/커팅 게이트에 이걸 쓰세요** — 델타가 아니라 레벨이라 노이즈에 강함 |
| — | 훈련연차, 성별, 나이 | **노이즈 0** | 사용자 입력. **최대한 활용할 것** |

> **모드 분류 담당에게 넘기는 한 줄:**
> **감량 vs 커팅을 ΔSMM으로 가르지 마세요.** 가장 잡음이 큰 신호입니다. **현재 PBF 레벨 + 훈련연차(사용자 입력, 무잡음)** 로 가르고, 델타는 *방향 확인*에만 쓰세요.

## 8. 오너 실제 궤적 판정

### 8.1 데이터

| 날짜 | 시각 | 체중 | SMM | PBF | BFM | FFM |
|---|---|---|---|---|---|---|
| 2026-06-30 | 07:36 | 89.0 | 36.2 | 28.4% | 25.3 | 63.7 |
| 2026-08-31 | 08:35 | 86.9 | 37.4 | 24.2% | 21.0 | 65.9 |
| 2026-09-19 | 11:09 | 86.7 | 37.9 | 23.1% | 20.0 | 66.7 |

**81일 델타:** 체중 **−2.3**, SMM **+1.7**, BFM **−5.3**, FFM **+3.0**, PBF **−5.3 %p**

### 8.2 에너지 수지 교차검증 — 여기서 모순이 드러납니다

**[유도]**
```
지방 5.3 kg × 7700 kcal/kg ÷ 81일 = 504 kcal/day 적자
TDEE (BMR 1810 × PAL 1.55)         = 2806 kcal
적자 비율 = 504 / 2806              = 18.0%  ← 엔진 기준 "real deficit" (>15%)
```

그런데 **엔진 자체 규칙**으로는:
- intermediate + real deficit ⇒ 근육 증가 계수 **×0.05** → 사실상 0
- intermediate 천장 0.75 %BW/월 FFM × 2.66개월 × 0.05 ≈ **+0.09 kg**
- 관측된 FFM 증가: **+3.0 kg** → **엔진 천장의 약 33배**

novice로 가정해도: 1.25 %BW/월 × 86.9 × 2.66개월 × 0.30(real deficit, novice) ≈ **+0.87 kg**. 여전히 관측치의 **1/3.4**.

**→ 관측된 FFM 증가는 엔진의 생리학적 천장을 어떤 설정으로도 넘습니다. 따라서 상당 부분이 실제 조직이 아닙니다.**

### 8.3 +3.0 kg FFM 분해 (내 추정 — 근거 명시)

| 성분 | 추정 | 근거 |
|---|---|---|
| **측정 시각 이동** (07:36 → 11:09, 3.5시간) | **+0.5 ~ +1.0 kg** | "오후가 오전보다 FFM 약 +1 kg"[검색요약]. 3.5시간이면 그 효과의 상당 부분. **마지막 스캔이 가장 늦은 시각** = 편향이 정확히 유리한 방향 |
| **글리코겐 + 훈련 수분/부종** | **+0.5 ~ +1.5 kg** | 3.1절 체인. Damas 부종[검색요약]. 6월 말 시작이면 8월 말 스캔 시점에 여전히 적재 중 |
| **수화도 상수 0.73 편향 이동** | **+0.3 ~ +0.8 kg** | PBF 28.4%→23.1%로 내려가며 실제 제지방 수화도가 77%대에서 73% 쪽으로 내려갔다면, 0.73 고정 공식이 FFM을 점점 덜 과대평가 → 하지만 부호가 반대. **역방향 가능성 있음** [미검증 — 방향 확정 못 함. 보수적으로 ±0.5 kg 불확실성으로 처리 권장] |
| **실제 제지방 조직 증가** | **+0.5 ~ +2.0 kg** | 나머지 |

**가장 단단한 사실 하나:**

> **체중은 −2.3 kg 움직였습니다. 이건 저울이 잰 겁니다.**
> 그런데 결과지는 **−5.3 kg 지방 감소**를 주장합니다. 그 차액 3.0 kg은 전부 "FFM이 늘었다"는 주장에서 나옵니다.
> **즉 "지방 5.3 kg 감량"의 신뢰도는 "근육 3.0 kg 증량"의 신뢰도와 정확히 같습니다.** 하나가 무너지면 둘 다 무너집니다. [유도]

### 8.4 그럼에도 — 방향은 진짜입니다

리컴프 자체를 부정하면 안 됩니다. 오너는 **교과서적인 리컴프 responder**입니다:

- **22세 남성** — 테스토스테론·회복력 최고 구간
- **시작 PBF 28.4%** — 저장 에너지가 충분. Barakat et al. 2020 (*Strength & Conditioning Journal*) [검색요약]: 리컴프는 **과체중/미훈련에서 가장 잘 일어나며**, 훈련자에서도 가능
- **PBF가 3회 연속 단조 감소** (28.4 → 24.2 → 23.1). 5.3 %p는 실사용 T_confident (3.3 %p)를 크게 상회
- **SMM도 3회 연속 단조 증가** (36.2 → 37.4 → 37.9). 우연한 잡음이 3회 같은 방향일 확률은 낮음
- **적자가 완만** — 18%는 엔진 기준으론 선을 넘었지만, 절대적으로는 하루 504 kcal로 온건

### 8.5 **판정**

> **방향: 진짜 리컴프. 크기: 약 40~60% 과장.**
>
> 정직한 재서술: **"81일간 체중 2.3 kg 감소 + 체지방률 확실한 감소 + 제지방 소폭 증가(대부분 수분일 가능성)."**
> 정직하지 않은 재서술: "근육 1.7 kg 늘리면서 지방 5.3 kg 뺐다."

**최근 19일(8/31→9/19)은 더 조심해야 합니다.** Δ체중 −0.2, ΔSMM +0.5, ΔBFM −1.0, ΔPBF −1.1 %p — **네 항목 전부 실사용 T_noise 이하이거나 경계**입니다. 게다가 간격이 **19일로 28일 게이트 미달**이고, 시각이 **11:09로 이전 대비 2.5시간 늦습니다**. 

> **앱이 이 마지막 스캔에 대해 해야 할 말: "간격이 19일이라 판정하지 않습니다. 게다가 이번엔 오전 11시에 재셨네요 — 이전보다 2~3시간 늦습니다. 그것만으로 근육 0.5 kg쯤은 달라 보입니다."**

### 8.6 **오너는 지금 어떤 모드인가 — 그리고 앱은 뭐라고 말해야 하나**

**현재 모드: 리컴프 (계속 유지).** 단, 한 가지를 고쳐야 합니다.

**[유도] 적자가 살짝 과합니다:**
```
엔진의 "mild deficit" 상한 = TDEE의 15% = 2806 × 0.15 = 421 kcal/day
                            = 0.383 kg/주 = 0.441 %BW/주
오너의 실제 진행           = 504 kcal/day = 18.0% of TDEE
```
> **오너는 리컴프가 성립하는 보호 구간(≤15%)을 살짝 넘겨서 달리고 있습니다.** 하루 **80~100 kcal만 더 먹으면** 엔진의 근육 증가 계수가 `×0.05 → ×0.70` (novice 기준 `×0.30 → ×0.70`)으로 **뛰어오릅니다.** 

이게 오너에게 줄 수 있는 가장 반직관적이고 가장 가치 있는 조언입니다: **"더 먹어야 더 빨리 목표에 갑니다."** 그리고 이건 이미 엔진이 계산할 수 있는 내용입니다 — README의 "강도를 올리면 오히려 느려질 수 있다" 경고와 정확히 같은 메커니즘입니다.

**앱 화면 문구 초안:**

> **지금 상태: 리컴프 진행 중 (실제로 잘 되고 있습니다)**
>
> 81일간 체중 2.3 kg ↓, 체지방률 28.4% → 23.1%. 방향은 확실합니다.
>
> ⚠️ **다만 결과지의 "근육 +1.7 kg"은 절반 정도만 믿으세요.** 운동 시작 초기의 글리코겐·수분이 근육으로 계산되고, 이번엔 측정 시각도 오전 11시로 평소보다 늦었습니다.
>
> 🔧 **조정 제안: 하루 80~100 kcal 더 드세요.**
> 지금 적자가 하루 약 500 kcal로, 근육을 지키면서 지방을 빼는 구간(약 420 kcal)을 살짝 넘었습니다. 조금 더 먹으면 감량 속도는 거의 그대로인데 근육 증가율이 크게 올라갑니다.
>
> 📌 **다음 인바디: 10월 17일 이후, 오전 7~8시, 공복으로.** (오늘처럼 11시에 재면 이전 기록과 비교가 안 됩니다)

**그리고 78.4 kg 적정체중에 대해:**

> "인바디가 제시한 78.4 kg은 **'근육을 하나도 안 늘린다고 치고'** 계산한 숫자입니다. 지금처럼 근육이 붙으면 이 숫자는 80~83 kg으로 올라갑니다. 체중 숫자 말고 **체지방률 15%**를 목표로 잡으세요 — 그게 실제로 원하시는 겁니다."

## 9. 모드 분류 담당에게 넘기는 인터페이스

내 스윕이 모드 자동선택 로직에 부과하는 제약:

```js
// 모드 선택기가 받아야 할 것 — 원시 델타가 아니라 '신뢰도 태그가 붙은' 델타
{
  weight:  { delta, confidence: 'high',   usable: true  },
  pbf:     { delta, confidence: 'medium', usable: true  },
  bfm:     { delta, confidence: 'medium', usable: true, dependentOn: ['weight','ffm'] },
  smm:     { delta, confidence: 'low',    usable: weeksTraining >= 8 },
  pbfLevel:{ value, confidence: 'stable', usable: true }, // ← 감량/커팅 게이트는 여기서
  interval: { days, adequate: days >= 28 },
  conditions: { standardized: bool, timeOfDayDriftHours: number }
}
```

**하드 규칙 4개:**
1. `interval.days < 28` ⇒ 모드 판정 자체를 거부하고 **유지** 반환 + 이유 표시
2. `weeksTraining < 8` ⇒ ΔSMM을 입력에서 제거 (0 처리 아님, **제거**)
3. 세 항목 모두 T_noise 미만 ⇒ **유지**
4. 감량/커팅 분기는 **ΔSMM이 아니라 PBF 레벨 + 훈련연차**로 (7.4절)

**그리고 오너의 원래 질문 — 감량 vs 커팅이 같은 건가 — 에 대한 InBody 측 입력:**
> 델타 데이터만으로는 **두 모드를 구분할 수 없습니다.** 둘 다 `Δ체중 <0, ΔBFM <0, ΔSMM ≈0` 입니다. 구분 가능한 유일한 신호는 **현재 PBF 레벨과 훈련연차** — 즉 **측정값이 아니라 사용자 입력**입니다. 따라서 이 둘을 별도 모드로 둘지는 측정 정확도 문제가 아니라 **UX/의도 문제**이고, 자동선택이 아니라 **사용자에게 한 번 묻는 게** 맞습니다.
