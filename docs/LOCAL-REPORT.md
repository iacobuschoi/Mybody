## ⚠ 먼저 — 릴리스 AAB 가 **서명이 안 돼 있습니다** (플레이 업로드 막힘)

`gh release download v0.2.3 -p "*.aab"` 로 받은 **mybody-v0.2.3-playstore.aab (83MB)** 는
`keytool -printcert -jarfile` → **"Not a signed jar file"**, `jarsigner -verify` → **"jar is unsigned"**.
zip 안에 루트 `META-INF/MANIFEST.MF`·`*.SF`·`*.RSA` 가 아예 없습니다. 콘솔에 올리면 거부됩니다.

**원인 (CI 로그에서 확인)** — `apk.yml` 의 「만들어졌는지 확인」 단계가

```
aab=$(find app/build -name '*.aab' | head -1)
```

로 찾는데, v0.2.3 을 만든 실행(35810264889)에서는 `find` 가 **서명 전 중간 파일**을 먼저 집었습니다:

```
app/build/app/intermediates/intermediary_bundle/release/packageReleaseBundle/intermediary-bundle.aab
```

같은 실행 로그에 제대로 나온 것은 `build/app/outputs/bundle/release/app-release.aab (32.2MB)` 입니다.
`find | head -1` 순서는 보장이 없어서 **판마다 서명된 것이 나올 수도, 안 나올 수도** 있습니다 —
실제로 오늘 CI 빌드(app-51) 꾸러미의 `bundle/release/app-release.aab` 는 **제대로 서명돼 있습니다**
(SHA256 `06d945a3…83de11`). 즉 서명 자체는 잘 되고, **고르는 데서만** 틀립니다.

**고칠 자리** — `.github/workflows/apk.yml` 213행쯤을 outputs 아래로 한정하면 됩니다:

```
aab=$(find app/build -path '*outputs/bundle/release/*' -name '*.aab' | head -1)
```

(APK 쪽은 `-name 'app-release.apk'` 라 우연히 안 걸렸습니다. v0.2.3 APK 는 지문 확인했고 정상입니다.)

**노트북에서 임시로 한 것** — 주인이 아침에 잘못 올리지 않도록, 바탕화면 폴더의
서명 안 된 파일은 `서명안된것-쓰지마세요/` 로 옮기고 사유를 적은 쪽지를 넣었습니다.
대신 **CI app-51 의 서명된 AAB 를 `mybody-build51-playstore.aab` (32MB, versionCode 51)** 로 넣고
폴더의 README.md 맨 위에 쪽지를 붙였습니다. 다음 릴리스가 고쳐져 나오면 그걸로 바꾸면 됩니다.
